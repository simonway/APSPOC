截至 2026-05-09，原二期路线图中此前未闭环的 `M4 / M5` 尾项已经补齐到当前代码基线：

- 已落地正式 `approve / reject` 审批流
- 已落地后端强校验的 `Admin / Planner / Approver / Viewer` 角色模型

## 2. 本次补齐项

### 2.1 M4 异步执行与运行稳定性

- 排程作业状态从原 `PENDING / RUNNING / DONE / FAILED` 扩展为完整目标态。
- 后端作业持久化增加 `actorUsername / sourceRequestJson / failureReason`。
- 新增：
  - `POST /api/v1/schedule/jobs/{jobId}/cancel`
  - `POST /api/v1/schedule/jobs/{jobId}/retry`
- 后端启动时会对 `CREATED / QUEUED / RUNNING` 的历史作业做恢复入队。
- 增加本地并发互斥，避免 `cancel` 与 worker 状态覆盖竞态。

### 2.2 M5 Gantt 与版本治理产品化

- 版本治理流由：
  - `DRAFT -> READY_FOR_RELEASE -> RELEASED`
  扩展为：
  - `DRAFT / REJECTED -> READY_FOR_RELEASE -> APPROVED -> RELEASED`
- 新增：
  - `POST /api/v1/versions/{versionId}/approve`
  - `POST /api/v1/versions/{versionId}/reject`
- 审计事件增加：
  - `APPROVE`
  - `REJECT`
- 版本对象增加 `createdBy`，治理动作继续通过审计流记录 actor/comment。
- 前端版本详情区已同步：
  - 提交审批
  - 审批通过
  - 驳回
  - 发布
  - 回退

### 2.3 角色权限

- 登录会话已返回 `username + role`
- 后端 API 权限已按角色收紧：
  - `Admin / Planner`：导入、场景生成、创建排程、取消/重试 job、提交审批
  - `Admin / Approver`：审批、驳回、发布、回退
  - `Viewer`：只读查看版本/Gantt/history
- 前端按钮状态已按角色同步禁用
