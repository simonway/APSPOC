# 2026-05-08 二期完成度与收尾建议

## 1. 结论

当前 APSPOC 不建议表述为“二期所有规划项已经全部完成”。

更准确的口径是：

> 二期核心能力完成，可进入业务演示/UAT；二期产品化收尾未全部完成。

这意味着：

- 业务主链路已经可以跑通：导入、场景生成、排程、版本、Gantt、diff、trial solve、发布/回退基础能力已可演示。
- 但如果按原始路线图逐项验收，仍有部分 `M4 / M5` 项未收口，暂不适合对外宣称“全部完成”。

## 2. 已完成的核心能力

### 2.1 主数据导入与场景生成

- 已支持 `Resource / Recipe / Demand / Downtime / InventoryBalance / SetupRule` 导入。
- 已支持模板导出、字段校验、错误报告、`dataVersion` 追踪。
- 已支持从导入批次生成场景，也支持直接生成场景。
- 已支持正式导入批次流与当前 backend 排程主链路衔接。

### 2.2 Solver UAT 最小能力

- 已支持 `Demand + Recipe -> Operation/Task` 展开。
- 已支持 `precedence` 约束。
- 已支持基础 `setupRules / changeover` 下传。
- 已支持 `materialInputs / materialOutputs / inventoryBalances`。
- 已支持库存覆盖需求的场景回放和 Gantt 展示。

### 2.3 Gantt 与版本治理基础

- 已支持版本列表、KPI、Gantt、history、diff。
- 已支持 diff 任务定位、高亮和状态反馈。
- 已支持 release note、`ready-for-release`、publish、rollback、audit history。
- 已支持 trial solve 与本地草稿交互。

### 2.4 UAT 演示资产

- 已有 `UAT_v1` 样本包。
- 已有 `snow_beer_packaging_v1` 样本包。
- 已补充适合前端 `导入 JSON` 的雪花演示文件：
  - [15_ui_import_demo_schedule_request.json](/Users/simon/Documents/MyProgramming/APSPOC/docs/sample-packages/snow_beer_packaging_v1/15_ui_import_demo_schedule_request.json:1)

## 3. 尚未完成的产品化收尾

### 3.1 M4 异步执行与运行稳定性

以下规划项目前未完成：

- Redis-backed queue 尚未接入主执行链路。
- Job 状态机未扩展到完整 `CREATED / QUEUED / RUNNING / SUCCEEDED / FAILED / TIMEOUT / CANCELLED`。
- 取消、重试、排队、并发限制未形成正式产品能力。
- `failureReason` 分类和可观测字段仍未完全达到规划口径。

### 3.2 M5 版本治理产品化

以下规划项目前仅部分完成：

- 当前已有 `READY_FOR_RELEASE / RELEASED / ROLLED_BACK` 基础流转，但尚无正式 `APPROVED / REJECTED` 审批流。
- 当前会话与后端接口未落地 `Admin / Planner / Approver / Viewer` 角色权限控制。
- actor attribution 已有基础审计，但尚未形成完整角色化审批/发布语义闭环。

## 4. 当前建议口径

### 4.1 对业务/UAT

建议使用以下说法：

- 当前版本已经具备二期核心业务能力，可以进入业务演示和 UAT 试用。
- 当前版本重点验证真实样本导入、场景生成、排程结果评审和版本治理基础能力。
- 正式审批流、角色权限和运行稳定性增强仍在后续收尾范围。

### 4.2 对研发/发布

发布前最少需要明确两件事：

1. 权限与审批口径  
   如果本版不落地正式审批流和角色权限，需要在文档、页面文案和发布说明中统一为“版本治理 MVP”，避免误导为完整审批产品。

2. 运行稳定性口径  
   需要明确当前不依赖 Redis queue，不支持完整 `cancel / timeout / queued` 产品语义，并在 runbook 中写清临时策略。

## 5. 下一步建议

按优先级建议如下：

1. 先完成 UAT 演示与业务反馈收集，验证当前二期核心能力是否满足最小业务口径。
2. 补齐 M5 中最容易引发认知偏差的部分：审批语义、角色权限、发布口径。
3. 评估 M4 是否在试点前必须补齐；如果多人并发和长耗时求解会成为常态，应优先接入稳定队列和完整状态机。
