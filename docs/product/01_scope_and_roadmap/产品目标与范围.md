## 2. 项目背景

- 当前业务场景：面向化工批次生产场景的 APS 排产 POC，当前系统已具备浏览器工作台、Spring Boot 编排服务、Python OR-Tools 求解器三层结构，可完成登录后发起排产、轮询任务、查看版本和甘特结果的基础闭环。
- 当前痛点：当前系统已经验证了排产引擎、停机窗口和版本化结果展示的可行性，但真实业务建模入口、主数据接入、版本差异分析、审计化回滚等能力尚未补齐，距离真实业务试点仍有明显差距。
- 触发本次建设的原因：先通过 POC 验证“异步排产 + 多资源约束 + 停机窗口 + 版本管理 + Gantt 可视化”的主链路是否成立，再逐步演进到接入真实数据和业务流程。
- 本阶段是 POC、试点还是正式上线项目：当前阶段属于 `Phase 1 POC baseline`，目标是验证产品方向和技术链路，而不是直接覆盖正式生产全流程。

## 3. 产品目标

### 3.1 业务目标

1. 验证化工生产排产场景中，系统自动生成可行方案的业务可行性。
2. 建立排产结果版本化沉淀机制，为方案评审、发布和后续审计打基础。
3. 形成一个可重复演示、可逐步接入真实数据的 APS 产品雏形。

### 3.2 用户目标

1. 让排产员能够在系统中快速触发一次排产，并明确看到任务状态、结果版本和甘特图。
2. 让生产管理人员能够通过 KPI、版本状态和发布时间快速评估当前方案。
3. 让系统使用者能够在统一工作台中完成登录、查看、发布和基础账号维护，而不依赖命令行或数据库操作。

### 3.3 项目目标

1. 打通前端工作台、后端编排服务和求解器的端到端链路。
2. 将当前能力沉淀为清晰的产品范围，为下一阶段 UI 建模、主数据接入和高级约束扩展提供边界。
3. 用一套稳定的 POC 文档和功能清单，支撑后续试点范围确认和研发排期。

## 5. 范围定义

### 5.1 本期范围内

- 登录、登出、会话校验、账号设置，中英双语切换。
- 一键运行样例排产场景，并以异步任务方式返回任务编号。
- 轮询查看排产任务状态，包括提交中、运行中、完成、失败。
- 后端持久化排产版本，并在前端展示版本列表、版本详情、KPI 和 Gantt 结果。
- 版本发布能力。
- 通用排产任务提交 API，支持传入资源、任务、停机窗口、目标权重和求解参数。
- Gantt 本地交互能力，包括缩放、详情面板、图例、任务拖拽草稿和冲突提示。

### 5.2 本期范围外

- 前端自定义排产建模页面，例如订单录入、资源维护、停机维护、参数配置表单。
- 主数据导入链路，例如 Recipe、Resource、Demand 等主数据接入。
- 版本差异对比、发布历史、完整回滚审计。
- Redis 队列化执行、回调机制和大规模任务调度能力。
- MES/ERP 等外围系统对接与生产执行闭环。
- 换型时间、工艺前后置关系、物料约束、库存约束等高级 APS 规则。

### 5.3 范围边界说明

| 边界主题 | 归属系统/团队 | 本项目负责内容 | 不负责内容 | 说明 |
| --- | --- | --- | --- | --- |
| 主数据 | 外部主数据系统/业务团队 | 定义未来接入边界，当前支持 API 直接传入 | 不负责主数据治理与正式主数据平台建设 | 当前主要通过样例数据和请求体模拟 |
| 订单/任务数据 | 外部业务系统/业务团队 | 提供通用排产请求接口 | 不负责订单来源系统建设 | 当前前端无真实录入页 |
| 设备停机与日历 | 设备/生产管理 | 支持以停机窗口方式参与排产 | 不负责设备状态实时采集 | 当前以请求体传入 |
| 排产求解 | APS POC | 负责候选资源分配、停机避让、到期惩罚和 makespan 优化 | 不负责高级约束闭环 | 当前目标函数和约束仍较精简 |
| 计划发布 | APS POC | 支持版本发布状态管理 | 不负责正式下发到 MES/执行系统 | 当前发布更偏方案确认状态 |

## 7. 约束与假设

### 7.1 业务约束

- 当前 POC 以样例场景和 API 直接建模为主，尚未覆盖真实业务录入链路。
- 当前排产模型以“任务 + 候选资源 + 停机窗口”为核心，尚未覆盖工艺路线、换型、库存等复杂约束。

### 7.2 技术约束

- 当前任务执行为应用内异步线程 + 轮询模式，Redis 虽已准备但尚未接入正式执行链路。
- 前端为静态页面，当前没有独立的复杂表单建模界面，交互重点仍是结果查看和演示。
- 当前回滚接口已存在，但业务语义和审计能力尚不完整，不能直接等同正式生产回滚。

### 7.3 项目假设

- 下一阶段会有明确的真实业务数据来源或最小主数据样本可供接入。
- POC 阶段允许先使用样例数据、API 请求体和人工验证来完成产品验证。
- 当前版本的首要目标是验证排产主链路，而不是一次性覆盖全部 APS 深度能力。
