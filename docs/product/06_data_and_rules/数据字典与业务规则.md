## 6. 规则表达

### BR-008 工序先后规则

- 规则目的：确保工艺路线顺序不被破坏。
- 适用范围：由 Recipe 展开的 Operation。
- 判断逻辑：同一 demand 下，`sequence=n+1` 的 Operation 开始时间必须 >= `sequence=n` 的结束时间。
- 结果处理：违反时 solver 不得返回该方案。
- 示例：反应完成后才能过滤，过滤完成后才能干燥。

### BR-009 基础换型规则

- 规则目的：反映同资源上产品/工艺切换需要准备时间。
- 适用范围：定义了 setupGroup 和 SetupRule 的资源任务。
- 判断逻辑：同一资源相邻任务若 `fromSetupGroup != toSetupGroup`，间隔至少为 `setupMinutes`。
- 结果处理：换型时间进入排程结果或 Gantt changeovers。
- 示例：A 产品切到 B 产品需要 60 分钟清洗。

### BR-010 导入校验规则

- 规则目的：防止脏数据进入排程主流程。
- 校验内容：必填、类型、枚举、引用、时间窗口、重复 ID、候选资源、Recipe-Demand 匹配。
- 结果处理：存在 P0 校验错误时，ImportBatch 为 VALIDATION_FAILED，不生成排产场景。

### BR-012 审批发布规则

- 规则目的：让正式版本发布成为受控业务动作。
- 判断逻辑：版本必须处于已提交/已审批状态，发布人具备 Approver/Admin 权限。
- 结果处理：发布成功后记录 actor、release note、前一发布版本。

## 8. 数据质量要求

| 质量项 | 要求 | 校验方式 | 处理方式 |
| --- | --- | --- | --- |
| 完整性 | 必填字段齐全 | 导入校验 / Bean Validation | 缺失则拒绝 |
| 准确性 | 引用真实存在，时间边界合法 | 后端显式校验 + solver 二次校验 | 返回错误报告 |
| 唯一性 | Resource、Recipe、Demand、Operation ID 在数据版本内唯一 | 导入校验 | 重复则拒绝 |
| 一致性 | Demand 必须有匹配 Recipe，Recipe 候选资源必须存在 | 导入校验 | 不生成场景 |
| 可追溯性 | 导入批次、场景、job、version 可串联 | dataVersion / sourceRequestJson | UAT 核对 |
| 可复现性 | 同一数据版本生成同一场景 | 数据版本冻结 | UAT 回归 |
