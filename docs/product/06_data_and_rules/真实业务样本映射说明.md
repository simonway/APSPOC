> 本文档用于指导将真实或脱敏真实业务资料映射为 APS MVP/UAT 可使用的数据包。当前目标是形成 UAT_v1 样本，而不是一次性完成全企业主数据治理。

## 2. 映射目标

UAT_v1 样本包需要支持以下闭环：

```text
真实/脱敏业务资料
  -> Resource / Recipe / Demand / Downtime / SetupRule 模板
  -> 导入校验
  -> dataVersion
  -> 排产场景
  -> Solver 请求
  -> 版本与 Gantt
  -> UAT 验收
```

## 3. 样本范围建议

| 维度 | MVP/UAT 建议 |
| --- | --- |
| 业务范围 | 一个车间/产线或一个代表性产品族 |
| 时间范围 | 7-14 天 horizon |
| 资源规模 | 20-50 个资源，第一轮可从 8-30 个开始 |
| 工序任务规模 | 100-300 个 Operation，第一轮可从 20-80 个任务开始 |
| 停机窗口 | 5-20 个 |
| 必含场景 | 多候选资源、固定资源/固定开始、停机避让、工序先后、迟交任务 |
| 可选场景 | 基础换型、试算、回退、审批发布 |

## 4. 数据模板清单

| 模板 | 用途 | 生成对象 | 优先级 |
| --- | --- | --- | --- |
| Resource 模板 | 资源/设备/产线清单 | Resource | P0 |
| Recipe 模板 | 产品工艺路线、工序、候选设备、标准工时 | Recipe / Operation | P0 |
| Demand 模板 | 订单/需求/批次、交期、优先级 | Demand | P0 |
| Downtime 模板 | 检修、清洗、停机、不可用窗口 | Downtime | P0 |
| SetupRule 模板 | 产品/工序/资源间换型时间 | SetupRule | P0/P1 |
| Request Context 模板 | 场景名称、起点、horizon、目标权重、求解参数 | Scenario | P0 |
| Data Issue Log | 数据缺口和待确认问题 | 数据质量清单 | P0 |

## 5. 字段映射规则

### 5.1 Resource 映射

| 源业务字段 | 目标字段 | 转换规则 | 必填 |
| --- | --- | --- | --- |
| 设备编码/产线编码 | `id` | 转成稳定英文/数字编码，不使用展示名作主键 | 是 |
| 设备名称 | `label` | 原样或脱敏后展示 | 是 |
| 设备类型 | `resourceType` | 映射为 REACTOR/TANK/FILTER/DRYER/OTHER 等 | 是 |
| 排序/区域 | `sortOrder` | 同区域内递增排序 | 是 |
| 容量 | `capacity` | 若 UAT 不涉及容量，可先保留为备注 | 可选 |

### 5.2 Recipe 映射

| 源业务字段 | 目标字段 | 转换规则 | 必填 |
| --- | --- | --- | --- |
| 产品编码 | `productCode` | 与 Demand 保持一致 | 是 |
| 工艺路线编号 | `recipeId` | 产品+版本或业务路线编码 | 是 |
| 工序编码 | `operationCode` | 同一 Recipe 内唯一 | 是 |
| 工序名称 | `operationName` | 原样或脱敏 | 是 |
| 工序顺序 | `sequence` | 从 1 开始递增 | 是 |
| 标准工时 | `durationMinutes` | 统一换算为分钟 | 是 |
| 可用设备 | `candidateResourceIds` | 映射到 Resource.id | 是 |
| 换型组 | `setupGroup` | 若启用基础换型则填写 | 可选 |

### 5.3 Demand 映射

| 源业务字段 | 目标字段 | 转换规则 | 必填 |
| --- | --- | --- | --- |
| 订单号/需求号 | `demandId` | 数据版本内唯一 | 是 |
| 产品编码 | `productCode` | 必须能匹配 Recipe | 是 |
| 数量/批量 | `quantity` | MVP 可先作为展示或批次数依据，需 M1 确认 | 可选 |
| 交期 | `dueAt` / `dueMinutes` | 统一换算为相对 scheduleStartAt 的分钟 | 是 |
| 优先级 | `priority` | 数值越大越重要，正整数 | 是 |
| 固定设备 | `fixedResourceId` | 若业务强制指定则填 | 可选 |
| 固定开始 | `fixedStart` | 若业务强制指定则填 | 可选 |

### 5.4 Downtime 映射

| 源业务字段 | 目标字段 | 转换规则 | 必填 |
| --- | --- | --- | --- |
| 停机编号 | `id` | 数据版本内唯一 | 是 |
| 设备编码 | `resourceId` | 映射到 Resource.id | 是 |
| 开始时间 | `startMinutes` | 相对 scheduleStartAt 的分钟 | 是 |
| 结束时间 | `endMinutes` | 相对 scheduleStartAt 的分钟，且大于开始 | 是 |
| 停机类型 | `downtimeType` | 例如 MAINTENANCE/CLEANING/CIP | 是 |
| 来源 | `source` | CALENDAR/MES/MANUAL | 可选 |
| 说明 | `description` | 原因描述 | 可选 |

### 5.5 SetupRule 映射

| 源业务字段 | 目标字段 | 转换规则 | 必填 |
| --- | --- | --- | --- |
| 前一产品/工序组 | `fromSetupGroup` | 与 Recipe.setupGroup 一致 | 是 |
| 后一产品/工序组 | `toSetupGroup` | 与 Recipe.setupGroup 一致 | 是 |
| 适用资源/类型 | `resourceId` / `resourceType` | 可空表示全局规则 | 可选 |
| 换型时间 | `setupMinutes` | 统一换算为分钟，>=0 | 是 |

## 6. 时间换算规则

- 所有排程内部时间统一为相对 `scheduleStartAt` 的分钟偏移。
- 真实时间必须先统一时区，再计算分钟差。
- `dueMinutes`、`startMinutes`、`endMinutes`、`pinnedStartMinutes` 必须落在 horizon 内。
- 若需求交期早于 scheduleStartAt，需要业务确认是否允许负值或转为紧急迟交任务；MVP 建议不接受负值。

## 7. 标识规则

- Resource、Recipe、Demand、Operation、Downtime 在同一 dataVersion 内必须唯一。
- 资源主键使用稳定编码，不使用中文名称或临时序号。
- Demand 与 Recipe 通过 `productCode` 关联。
- Recipe 与 Resource 通过 `candidateResourceIds` 关联。
- Downtime 与 Resource 通过 `resourceId` 关联。

## 8. 校验规则

| 校验项 | 错误示例 | 处理方式 |
| --- | --- | --- |
| 必填字段 | demandId 为空 | 拒绝导入，返回行级错误 |
| 类型错误 | durationMinutes 为文本 | 拒绝导入 |
| 引用错误 | candidateResourceIds 包含不存在资源 | 拒绝导入或场景生成 |
| 重复 ID | 两行 resourceId 相同 | 拒绝导入 |
| 时间错误 | downtime start >= end | 拒绝导入 |
| Recipe 缺失 | Demand.productCode 找不到 Recipe | 不生成场景 |
| setup 缺失 | 需要换型但找不到规则 | 根据 Must/Should 决定拒绝或警告 |

## 9.1 当前样本包语义审计约定（2026-05-09 补充）

对于当前已落地的雪花样本，建议把以下文件职责固定下来：

| 文件 | 用途 | 当前建议口径 |
| --- | --- | --- |
| `00_readme.md` | 人工阅读的业务映射说明 | 写清 `lot`、`priority`、需求切片、样本边界和 UAT 重点 |
| `08_generated_schedule_request.json` | 真正提交给 backend/solver 的执行请求 | 机器执行文件 |
| `09_uat_expected_checks.md` | 预期检查清单 | 样本规模、数量、前后置、换型、桥接修正等检查项 |
| `10_generated_operation_metadata.json` | 语义事实源 | 解释请求是如何由样本 CSV 展开出来的 |

当前雪花样本口径说明：

- `Demand.quantity` 使用预聚合 `lot`，不是原始 `KL`
- `priority` 是样本设计时冻结的业务紧急度，不是原始业务资料直接字段
- `requestedQuantity` 来自 `04_demands.csv`
- `inventoryCoveredQuantity` 由 `14_inventory_balances.csv` 在场景生成时分配得到
- `plannedQuantity = requestedQuantity - inventoryCoveredQuantity`
- `operations` 表示真实可执行工序节点
- `precedencePairs` 表示显式工序依赖边
- `setupRules` 表示换型矩阵快照
- `bridgeAdjustments` 表示样本桥接层是否做过兼容修正

推荐验收顺序：

1. 先看 `00_readme.md`，确认样本建模假设。
2. 再看 `04_demands.csv / 14_inventory_balances.csv`，确认输入口径。
3. 然后看 `10_generated_operation_metadata.json`，确认需求覆盖、工序展开、前后置、换型和桥接修正。
4. 最后再看 `08_generated_schedule_request.json` 和最终 Gantt，确认执行结果。

## 10. 完成判定

UAT_v1 样本准备完成需满足：

- Resource、Recipe、Demand、Downtime 至少一套数据完整。
- 所有 P0 字段有来源和转换规则。
- 所有引用关系可校验通过。
- Must 约束对应数据存在，例如 precedence、downtime、fixed、due/priority。
- 数据问题清单中没有阻断项。
- 样本可生成排产请求并进入 solver。
- 若样本宣称支持库存覆盖、前后置或换型验证，则 `10_generated_operation_metadata.json` 中对应字段必须可审计：
  - 库存覆盖：`demandCoverages`
  - 前后置：`precedencePairs`
  - 换型：`setupRules`
  - 桥接修正：`bridgeAdjustments`
