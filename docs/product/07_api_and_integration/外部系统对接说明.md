> 本文档说明 APS MVP/UAT 阶段与外部系统的对接边界。当前策略是“文件导入 + API 契约先行”，不把正式 ERP/MES 双向闭环作为 UAT 阻塞项。

## 2. 当前对接现状

当前已存在的系统间集成：

```text
Browser UI (8080)
  -> Backend API (8081)
       -> PostgreSQL
       -> Solver API (8000)

Redis:
  已 provision，下一阶段用于队列化执行或等价稳定方案评估
```

尚未正式集成：

- ERP / 订单系统。
- MES / 执行系统。
- 主数据系统。
- 企业级身份认证系统。

## 3. MVP/UAT 对接原则

1. UAT 不依赖正式 ERP/MES 双向集成。
2. 真实样本优先通过标准模板导入，保证可复现和可排障。
3. API 契约同步定义，便于后续联调。
4. 外部系统数据主权需明确，但 APS 不负责主数据治理。
5. 已发布版本输出需先稳定版本语义，再考虑下发 MES。

## 4. 系统职责边界

| 系统 | MVP/UAT 职责 | 是否 UAT 必需 | 说明 |
| --- | --- | --- | --- |
| Frontend UI | 登录、导入、排程、Gantt、审批发布 | 是 | 当前静态工作台继续演进 |
| Backend API | 认证、导入、编排、版本、审计、对接 solver | 是 | 核心中枢 |
| Solver API | 求解 Must 约束和返回结果/失败原因 | 是 | 内部服务 |
| PostgreSQL | 持久化 job/version/Gantt/audit/import | 是 | 主链路存储 |
| Redis | 队列/状态稳定性 | P0/P1 | 视 UAT 长任务和多人需求决定 |
| ERP | Demand 来源 | 否，先文件/API 契约 | 后续正式集成 |
| MES | Downtime/执行反馈/计划接收 | 否，先契约 | 后续正式集成 |
| 主数据系统 | Resource/Recipe/SetupRule 来源 | 否，先模板导入 | 后续正式集成 |

## 5. 外部数据输入边界

### 5.1 Resource / 主数据

- 推荐 UAT 输入方式：Excel/CSV 模板导入。
- 后续正式来源：主数据系统或设备台账。
- APS 责任：消费资源数据、校验引用、用于排程和 Gantt。
- APS 不负责：设备编码体系治理、组织架构主数据治理。

### 5.2 Recipe / 工艺路线

- 推荐 UAT 输入方式：Recipe 模板导入。
- 后续正式来源：工艺系统、主数据系统或工艺台账。
- APS 责任：展开 Operation、生成 precedence、候选资源和标准工时。
- APS 不负责：工艺路线审批和版本治理。

### 5.3 Demand / 订单需求

- 推荐 UAT 输入方式：Demand 模板导入。
- 后续正式来源：ERP/订单系统。
- APS 责任：转换为待排需求、交期和优先级。
- APS 不负责：订单创建、订单变更审批、客户交付承诺源头。

### 5.4 Downtime / 停机窗口

- 推荐 UAT 输入方式：Downtime 模板导入。
- 后续正式来源：MES、设备日历、维修计划。
- APS 责任：将不可用窗口纳入排程约束。
- APS 不负责：设备状态实时采集和停机审批。

### 5.5 SetupRule / 换型规则

- 推荐 UAT 输入方式：SetupRule 模板或配置导入。
- 后续正式来源：工艺规则、历史经验、主数据。
- APS 责任：在 solver 中表达基础换型时间。
- APS 不负责：复杂清洗验证和质量放行逻辑。

## 6. 输出边界

| 输出对象 | MVP 输出方式 | 后续集成方向 |
| --- | --- | --- |
| 版本列表 | Backend API / UI | ERP/MES 可查询 |
| Gantt 数据 | Backend API / UI | MES 下发/看板展示 |
| 已发布计划 | UI/API/导出 | MES 执行接收 |
| 审计历史 | UI/API | 管理审计/合规报表 |
| UAT 报告 | 文档 | 项目治理 |

## 7. 推荐对接模式

| 阶段 | 模式 | 说明 |
| --- | --- | --- |
| M0-M2 | 文件导入为主 | 最快支撑真实样本和 UAT 可复现 |
| M2-M5 | API 契约同步定义 | 为后续系统联调降低返工 |
| M6 后 | 选择一个外部系统试联调 | 通常先 ERP/Demand 或主数据/Resource/Recipe |
| 后续正式集成 | API/MQ/文件按对方能力选型 | 不在当前 MVP 阻塞范围 |

## 8. 数据主权与责任划分

| 数据主题 | 权威系统/负责人 | APS 是否可编辑 | MVP 策略 |
| --- | --- | --- | --- |
| Resource | 主数据/设备台账 | 试点期可导入，不做主权系统 | 模板导入 + 校验 |
| Recipe | 工艺/主数据 | 试点期可导入 | 模板导入 + version 记录 |
| Demand | ERP/业务计划 | 试点期可导入 | 模板导入 + dataVersion |
| Downtime | MES/设备日历/人工 | 试点期可导入 | 模板导入 + 来源字段 |
| ScheduleJob | APS | APS 内部生成 | 持久化追踪 |
| ScheduleVersion | APS | APS 内部生成 | 审批发布治理 |
| Released Plan | APS 输出，MES 接收 | APS 发布，MES 执行 | 先定义字段，不正式下发 |

## 9. 对接非功能要求

| 主题 | 要求 |
| --- | --- |
| 幂等性 | 导入和同步需避免重复数据造成状态混乱 |
| 校验 | 外部输入进入 solver 前必须完成字段和引用校验 |
| 可追溯 | dataVersion、jobId、versionId 可串联 |
| 容错 | 外部系统不可用不影响已生成版本查看 |
| 安全 | 正式系统集成时需服务间鉴权，不只依赖浏览器 session |
| 审计 | 导入、生成、发布、回退需记录 actor 和时间 |

## 10. 分阶段对接建议

| 阶段 | 对接重点 |
| --- | --- |
| V1 / M0-M1 | 明确试点范围、数据来源、字段口径和样本责任人 |
| V2 / M2 | 完成模板导入和 API 契约，不依赖正式外部系统 |
| V3 / M3-M4 | 将 solver 契约扩展为 Operation、precedence、setup |
| V4 / M5 | 稳定版本治理语义，再定义已发布计划输出 |
| V5 / M6 | UAT 结束后决定首个正式联调对象 |
| V6 后续 | ERP/MES/主数据正式集成和执行反馈闭环 |

## 11. 待确认问题

| 编号 | 问题 | 影响对象 | 建议决策时点 |
| --- | --- | --- | --- |
| INT-01 | UAT 样本由哪个业务系统或负责人提供？ | Resource/Recipe/Demand/Downtime | M0 |
| INT-02 | 首个正式联调对象是 ERP、MES 还是主数据系统？ | 后续集成 | M6 后 |
| INT-03 | 已发布计划输出字段集是什么？ | MES/下发 | M5-M6 |
| INT-04 | 正式集成采用 API、文件还是 MQ？ | 架构 | V6 |
| INT-05 | 是否需要服务间鉴权和接口签名？ | 安全 | V6 前 |

## 12. 当前建议下一步

1. M0 先确认数据来源负责人和样本冻结日期。
2. M1/M2 先完成模板导入和 dataVersion 追踪。
3. M5 之前稳定发布/审批/回退语义，再讨论下发 MES。
