> 本文档用于说明 APS POC 当前已经存在的系统间集成，以及下一阶段与 ERP、MES、主数据系统等外部系统的推荐对接边界。

## 2. 当前对接现状概述

### 2.1 当前已存在的系统间集成

- 前端工作台 -> Backend API：浏览器通过 HTTP + Session Cookie 访问后端业务接口。
- Backend API -> Solver API：后端将标准排产请求转换后，通过 HTTP 调用求解器 `/api/v1/solve`。
- Backend API -> PostgreSQL：后端持久化排产任务和版本结果。

### 2.2 当前尚未实现的外部系统对接

- ERP / 订单系统输入。
- 主数据系统输入（资源、工艺、日历等）。
- MES / 执行系统输出。
- 真正的企业级身份认证系统接入。

### 2.3 当前定位

- 当前阶段仍属于 POC 基线，外部系统对接以“定义边界”为主，不以“已完成正式集成”为目标。

## 3. 当前系统拓扑

```text
Browser UI (8080)
  -> Backend API (8081)
       -> PostgreSQL
       -> Solver API (8000)

Redis:
  已 provision，但当前未接入正式执行链路
```

## 5. 当前已实现的对接说明

### 5.1 Frontend UI -> Backend API

| 项目 | 说明 |
| --- | --- |
| 协议 | HTTP/JSON |
| 认证方式 | Session Cookie |
| 当前调用接口 | Auth / Schedule Jobs / Versions / Health |
| 特点 | 前端不直接访问求解器；所有业务操作先经过后端 |
| 当前限制 | 无真实业务录入页，主要通过样例排产和结果查看驱动 |

### 5.2 Backend API -> Solver API

| 项目 | 说明 |
| --- | --- |
| 协议 | HTTP/JSON |
| 当前调用路径 | `POST /api/v1/solve` |
| 请求来源 | Backend 将排产请求转换为 SolverRequest |
| 响应内容 | 求解状态、scheduledTasks、kpis |
| 超时策略 | 当前连接超时 5 秒，整体求解时间由 solverConfig 控制 |
| 当前限制 | 仅支持当前约束模型，未覆盖高级 APS 规则 |

### 5.3 Backend API -> PostgreSQL

| 项目 | 说明 |
| --- | --- |
| 存储对象 | ScheduleJob、ScheduleVersion |
| 当前用途 | 查询任务状态、加载版本列表、查看 Gantt 结果、发布版本 |
| 当前限制 | 当前只支持基础版本治理，未补完整审计 |

## 6. 未来对接对象与建议边界

### 6.1 主数据系统

#### 建议对接对象

- 资源/设备主数据。
- 停机日历或设备不可用日历。
- 后续可能扩展：工艺路线、设备能力、换型规则。

#### 建议边界

| 主题 | 建议来源系统 | APS 责任 | 备注 |
| --- | --- | --- | --- |
| 资源主数据 | 主数据系统 | 消费并用于排产 | APS 不做主数据治理 |
| 停机日历 | 主数据系统/设备维护系统 | 读取并参与排产 | 可允许人工补充 |
| 工艺/路线 | 主数据系统或工艺系统 | 后续作为高级约束输入 | 当前阶段不强制 |

#### 建议阶段

- V1：先明确字段边界，必要时支持手工导入。
- V3：视试点需要接入正式系统。

### 6.2 ERP / 订单 / 需求系统

#### 建议对接对象

- 订单、需求、交期、优先级。

#### 建议边界

| 主题 | 建议来源系统 | APS 责任 | 备注 |
| --- | --- | --- | --- |
| 订单/需求 | ERP 或订单系统 | 转换为可排产任务对象 | APS 不负责原始订单管理 |
| 交期与优先级 | ERP/业务规则 | 参与排产目标函数 | 建议保留人工调整入口 |

#### 建议阶段

- V1：可先人工录入或导入最小订单样本。
- V3：进入正式 ERP 对接。

### 6.3 MES / 执行系统

#### 建议对接对象

- 已发布版本对应的执行计划。
- 后续可能扩展：执行反馈、计划回传、偏差闭环。

#### 建议边界

| 主题 | APS 输出 | MES 责任 | 备注 |
| --- | --- | --- | --- |
| 已发布计划 | 版本摘要、任务分配、时间安排 | 执行接收与落地 | 当前尚未实现下发 |
| 执行反馈 | 后续由 MES 返回实际执行信息 | APS 用于后续优化闭环 | 当前不在范围内 |

#### 建议阶段

- V3：先明确发布版本的输出口径和字段。
- 后续阶段：再考虑执行反馈闭环。

## 7. 推荐对接模式

| 对接对象 | 当前建议模式 | 适用阶段 | 原因 |
| --- | --- | --- | --- |
| 主数据系统 | 先文档化字段边界，必要时手工导入/文件导入 | V1 | 降低初期对接复杂度 |
| ERP/订单系统 | 先 API/文件双方案预留 | V1-V3 | 便于适配不同企业 IT 条件 |
| MES | 先定义输出模型，再决定 API/文件/消息 | V3 | 必须先稳定版本语义 |
| Solver | 继续沿用内部 HTTP API | 当前/V1/V2 | 现有边界已清晰 |

> 建议原则：优先 API，对方系统受限时可接受 CSV/Excel/JSON 文件中转，但需保证字段口径一致。

## 8. 数据主权与责任划分

| 数据主题 | 权威系统 | APS 是否可编辑 | 当前建议 |
| --- | --- | --- | --- |
| 资源/设备 | 主数据系统 | 原则上否，允许试点期人工补录 | V1 先明确来源边界 |
| 停机日历 | 设备/日历系统或人工补充 | 可部分补录 | 试点期允许人工维护 |
| 订单/需求 | ERP/订单系统 | 原则上否，允许试点期导入 | V1 先支持最小样本 |
| 排产任务 Job | APS | 否 | APS 内部编排对象 |
| 排产版本 Version | APS | 否 | APS 内部结果对象 |
| 已发布计划 | APS 输出，MES 接收 | 否 | 需明确输出格式 |

## 9. 对接过程中的非功能要求

| 主题 | 要求 |
| --- | --- |
| 幂等性 | 导入、同步和发布动作应避免重复写入造成状态混乱 |
| 校验 | 外部输入在进入求解前必须完成字段校验和引用合法性校验 |
| 可追溯性 | 至少能定位一次导入、一次排产、一次发布分别使用了哪批数据 |
| 容错 | 外部系统不可用时，不应拖垮当前排产查看和版本浏览能力 |
| 安全 | 外部系统接入时应补服务间鉴权策略，不继续仅依赖浏览器登录态 |

## 10. 分阶段对接建议

### 当前阶段（V0）

- 不做正式 ERP/MES/主数据系统对接。
- 先通过样例和通用 API 验证排产主链路。

### 下一阶段（V1）

- 明确最小主数据和订单输入边界。
- 视资源情况选择：真实录入页优先，或最小文件导入优先。

### 再下一阶段（V2）

- 以版本治理为主，不建议同时大规模推进外部系统联调。

### 试点准备阶段（V3）

- 优先接一个最关键的输入系统（通常是主数据或 ERP）。
- 在版本语义稳定后，再定义向 MES 输出已发布计划的方式。
