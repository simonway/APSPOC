# 术语表

## 1. 说明

本文档用于统一 APS POC 项目中的业务、产品、算法和技术术语，减少产品、业务、研发、算法、测试在沟通时的歧义。

## 2. 业务与产品术语

| 术语 | 英文/缩写 | 定义 | 当前项目中的含义 |
| --- | --- | --- | --- |
| APS | Advanced Planning and Scheduling | 高级计划与排程系统 | 本项目要验证的核心业务系统方向 |
| POC | Proof of Concept | 概念验证 | 当前项目阶段，目标是验证主链路和方向可行性 |
| 排产 | Scheduling | 将任务分配到资源并安排时间 | 当前核心业务能力 |
| 排产任务 | Schedule Job | 一次后台异步排产执行 | 由用户触发，状态会流转到 DONE 或 FAILED |
| 排产版本 | Schedule Version | 一次成功排产后的结果快照 | 用于查看、发布和后续治理 |
| 方案 | Plan / Schedule Plan | 一组可执行排产结果 | 当前通常对应一个版本 |
| 发布版本 | Published Version | 当前确认采用的版本 | 当前系统始终只保留一个已发布版本 |
| 草稿版本 | Draft Version | 尚未被确认发布的版本 | 新生成版本的默认状态 |
| 归档版本 | Archived Version | 被新发布版本替代的旧版本 | 用于保留历史结果 |
| 版本治理 | Version Governance | 对版本的发布、回退、比较、审计管理 | 当前仅部分实现，后续增强 |
| 样例排产 | Sample Schedule | 使用系统内置样例数据发起排产 | 当前 POC 的主演示入口 |
| 真实业务录入 | Real-world Modeling Input | 录入或导入真实业务数据 | 当前未实现，是下一阶段重点 |
| 试点 | Pilot | 在真实业务环境的小范围验证 | 当前尚未进入正式试点 |

## 3. 业务对象术语

| 术语 | 英文/缩写 | 定义 | 当前项目中的含义 |
| --- | --- | --- | --- |
| 资源 | Resource | 可被安排任务的设备/产线单元 | 当前包括 REACTOR、TANK、FILTER、DRYER 等 |
| 资源类型 | Resource Type | 资源分类 | 当前以枚举区分资源类别 |
| 任务 | Task | 需要被安排执行的作业单元 | 当前由请求体或样例场景提供 |
| 产品编码 | Product Code | 任务对应产品的标识 | 当前主要用于展示与识别 |
| 候选资源 | Candidate Resource IDs | 某任务允许落到的资源集合 | 求解器会从中择一分配 |
| pinned 资源 | Pinned Resource | 被固定到指定资源的任务约束 | 当前已支持 |
| pinned 开始时间 | Pinned Start | 被固定到指定开始时间的任务约束 | 当前已支持 |
| 停机窗口 | Downtime | 资源不可用的时间段 | 当前已进入排产模型与 Gantt 展示 |
| 停机类型 | Downtime Type | 停机分类 | 如 MAINTENANCE、CIP 等，当前未正式枚举化 |
| 场景 | Scenario | 一次排产的输入上下文 | 通过 `scenarioName` 标识 |
| 时域 | Horizon | 本次排产允许规划的时间跨度 | 通过 `horizonMinutes` 定义 |
| 任务交期 | Due Minutes / Due Date | 任务期望完成时点 | 相对排产起点的分钟数 |
| 优先级 | Priority | 任务重要程度 | 当前数值越大表示越重要 |

## 4. 算法与结果术语

| 术语 | 英文/缩写 | 定义 | 当前项目中的含义 |
| --- | --- | --- | --- |
| 求解器 | Solver | 负责计算排产结果的引擎 | 当前为 Python FastAPI + OR-Tools |
| 可行解 | FEASIBLE | 满足约束的可用排程结果 | 求解成功的一种状态 |
| 最优解 | OPTIMAL | 在当前目标函数下最优的排程结果 | 求解成功的一种状态 |
| 无解/失败 | FAILED / no feasible schedule | 无法得到有效方案或执行异常 | 任务状态会变为 FAILED |
| 目标函数 | Objective Function | 用于评价方案优劣的优化目标 | 当前关注 tardiness 和 makespan |
| 加权延迟总量 | Total Weighted Tardiness | 延迟时间乘以优先级后的总和 | 当前 KPI 之一 |
| 总工期 | Makespan | 所有任务最晚结束时间 | 当前 KPI 之一 |
| 延迟任务数 | Late Task Count | 超过交期的任务数量 | 当前 KPI 之一 |
| 排程效率 | Schedule Efficiency | 仅基于实际参与排程资源计算的忙碌程度 | 当前 KPI 之一，对外展示兼容使用 `averageUtilization` 字段 |
| Gantt | Gantt Chart | 甘特图/资源时间轴视图 | 当前前端主要结果展示方式 |
| 任务条 | Bar | Gantt 中表示任务的条形块 | 对应任务在某资源上的排程结果 |
| 资源行 | Row | Gantt 中的资源时间轴行 | 对应一个资源 |
| 本地草稿 | Local Draft | 用户在前端本地拖拽后形成的临时结果 | 当前不回写后端 |
| 冲突 | Conflict | 本地草稿与其他任务或停机重叠 | 当前前端会做可视化提示 |
| changeover | Changeover | 任务切换/换型时间 | 当前字段已预留，但未正式实现 |

## 5. 状态术语

### 5.1 任务状态

| 状态 | 定义 | 当前含义 |
| --- | --- | --- |
| PENDING | 已创建未开始执行 | 后台 job 初始状态 |
| RUNNING | 正在执行中 | 后台正在调用求解器 |
| DONE | 已完成 | 成功求解并生成版本 |
| FAILED | 已失败 | 求解失败或执行异常 |

### 5.2 版本状态

| 状态 | 定义 | 当前含义 |
| --- | --- | --- |
| DRAFT | 草稿 | 新生成版本的默认状态 |
| PUBLISHED | 已发布 | 当前确认采用的版本 |
| ARCHIVED | 已归档 | 被后续已发布版本替代的历史版本 |

### 5.3 前端草稿状态

| 状态 | 定义 | 当前含义 |
| --- | --- | --- |
| Clean | 无本地修改 | 当前只显示已保存版本结果 |
| Dirty | 有本地草稿 | 用户已拖拽任务形成局部调整 |
| Conflict | 草稿冲突 | 本地草稿与任务/停机重叠 |

## 6. 技术与架构术语

| 术语 | 英文/缩写 | 定义 | 当前项目中的含义 |
| --- | --- | --- | --- |
| Frontend UI | Frontend | 用户看到的工作台界面 | 当前为静态 HTML/CSS/JS |
| Backend API | Backend | 业务编排与接口层 | 当前为 Spring Boot |
| Solver API | Solver | 算法求解服务 | 当前为 FastAPI + OR-Tools |
| PostgreSQL | Postgres | 关系型数据库 | 当前用于保存任务和版本 |
| Redis | Redis | 内存型数据存储/队列常用组件 | 当前已 provision，但未接主链路 |
| Session Cookie | Session | 浏览器会话认证方式 | 当前后端接口鉴权方式 |
| API 契约 | API Contract | 接口路径、字段、响应约定 | 当前已在接口文档中统一 |
| 主数据 | Master Data | 相对稳定的业务基础数据 | 当前尚未正式接入主数据系统 |
| ERP | Enterprise Resource Planning | 订单/计划/经营系统 | 未来可能提供订单与需求输入 |
| MES | Manufacturing Execution System | 制造执行系统 | 未来可能接收已发布计划 |

## 7. 当前容易混淆的概念

| 概念 A | 概念 B | 区别 |
| --- | --- | --- |
| 排产任务 Job | 排产版本 Version | Job 是后台执行过程；Version 是成功执行后的结果快照 |
| 草稿版本 DRAFT | 本地草稿 Local Draft | 草稿版本保存在后端；本地草稿只存在前端内存 |
| 发布 Publish | 回滚 Rollback | 当前接口上都能切版本状态，但 rollback 真实业务语义尚未正式定义 |
| 样例排产 | 真实业务录入 | 前者依赖系统内置数据；后者面向真实业务数据 |
| 对接边界已定义 | 系统已完成集成 | 文档定义边界不代表正式联调已经完成 |

## 8. 使用建议

- 在后续 PRD、设计、测试、联调文档中，优先使用本术语表中的标准名称。
- 若出现新术语，先补入本术语表，再进入其他正式文档。
- 如果某术语在业务和技术两个语境下含义不同，应在文档中明确注明。
