## 当前状态补记（2026-05-08）

当前版本推荐统一口径为：

> 二期核心能力完成，可进入业务演示/UAT；二期产品化收尾未全部完成。

因此本清单默认按“当前真实已落地能力”组织检查项：

- 默认按当前已实现的统一登录态、导入/场景生成/排程/Gantt/版本治理基础流验收。
- `Admin / Planner / Approver / Viewer` 角色模型、正式 `approve / reject` 审批流、Redis-backed queue、完整 `QUEUED / TIMEOUT / CANCELLED` 状态机，不作为当前版本默认必检前提。
- 如果某次发布对外额外宣称上述能力，则必须在本清单基础上追加专项验收。

- 不承诺正式生产可用。
- 不承诺完整 ERP/MES 双向闭环。
- 不承诺复杂库存、公用工程、人员班组、任务拆分/合批已覆盖。
- 不承诺 Gantt 本地拖拽等于正式计划变更。
- 不承诺完整企业级权限、SSO、多级审批和生产 SLA。
- 不承诺 Redis-backed queue 和完整 `QUEUED / TIMEOUT / CANCELLED` 产品语义已落地。
- 不承诺正式 `approve / reject` 审批流和 `Admin / Planner / Approver / Viewer` 后端权限模型已落地。

## 12. 建议下一步

- UAT 发布前必须完成当前版本真实口径确认，避免把“核心能力完成”误说成“全部产品化完成”。
- 若 Redis-backed queue 未接入，需要明确长任务和失败恢复临时策略。
- 若正式审批流和角色权限仍未落地，需要在发布说明、runbook 和演示话术中明确当前仅为版本治理 MVP。
- UAT 结束后基于缺陷和业务反馈决定 V6 高级 APS / 正式集成范围。
