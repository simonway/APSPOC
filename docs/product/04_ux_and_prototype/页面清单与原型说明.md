> 本文档基于当前前端实际实现整理页面结构，并补充下一阶段 MVP/UAT 需要新增的页面能力。当前系统仍以单页工作台为主，但业务重心将从“样例演示”扩展到“导入真实样本、评审版本、审批发布”。

## 2. 设计原则

- 核心任务优先：围绕“导入/生成场景、排程、评审、审批、发布”组织页面。
- 先稳主流程：优先复用现有工作台与 Gantt，不先做复杂页面重构。
- 结果可解释：版本、KPI、Gantt、差异、异常任务信息要能一起看。
- 治理明确：草稿、待审批、已发布、历史版本需要被用户明显区分。
- 数据可追溯：页面上能看到 dataVersion、jobId、versionId 和关键说明。

## 5. 当前页面详细说明

### P-01 登录页

- 当前目标：登录 + 语言切换。
- 保持不变：左侧视觉区、右侧表单区和错误反馈。
- MVP 增强：可显示登录后角色名称或环境提示（如 UAT 环境）。

### P-02 主工作台

- 当前目标：运行样例、刷新数据、进入版本查看。
- MVP 增强：
  - 顶部区增加 Import / Generate Scenario 入口。
  - 显示当前角色、当前 dataVersion、最近一个 job 状态。
  - 对 Viewer 隐藏创建/审批/发布操作。

### P-03 版本列表与摘要区

- 当前目标：查看版本列表、状态、KPI、基础操作。
- MVP 增强：
  - 显示草稿/待审批/已发布/已归档状态。
  - 增加 diff、history、audit、异常任务入口。
  - 增加 release note、actor attribution 摘要。

### P-04 Gantt 结果区

- 当前目标：查看 Gantt、本地草稿、冲突、试算。
- MVP 增强：
  - 支持按订单/产品/资源/异常任务定位和筛选。
  - 支持展示迟交、固定任务、setup 影响、警告信息。
  - 明确草稿/正式版本边界提示。

### P-05 账号设置弹窗

- 当前目标：修改用户名和密码。
- MVP 增强：角色变化后仅显示当前用户允许的字段；不扩展成完整用户管理后台。

## 6. MVP 新增页面/区域说明

### P-06 主数据导入入口

#### 页面目标

- 让 Planner/Admin 能导入 UAT_v1 样本。

#### 关键内容

- 选择导入对象：Resource、Recipe、Demand、Downtime、SetupRule。
- 上传文件、查看校验结果、下载错误报告。
- 展示 dataVersion、导入人、导入时间。

#### 验收重点

- 错误可定位到 sheet/行/字段。
- 导入失败不会进入排程主流程。

### P-07 场景生成与导入结果

#### 页面目标

- 展示由 dataVersion 生成的场景摘要和转换结果。

#### 关键内容

- 当前 dataVersion。
- Resource/Recipe/Demand/Downtime 数量。
- 生成的 Operation 数量、约束摘要、horizon、目标权重、solver 参数。
- 生成失败原因。

#### 验收重点

- 同一 dataVersion 可复现场景。
- 失败原因可理解。

### P-08 审批/发布说明区

#### 页面目标

- 让版本治理动作更清晰、更可追溯。

#### 关键内容

- release note 编辑。
- 提交审批按钮。
- Approver 的批准/驳回按钮。
- 发布按钮。
- 回退/复制历史版本说明。
- 当前版本的创建人、提交人、审批人、发布人。

#### 验收重点

- 未审批版本不可直接发布。
- 角色按钮显隐和后端权限一致。

## 8. 当前建议的原型补充重点

1. 导入入口与错误报告交互。
2. 版本摘要中 actor attribution 和 release note 的位置。
3. Gantt 上按异常任务定位的交互。
4. 审批/驳回/发布/回退的治理区布局。
5. Viewer 角色下的只读态页面表现。

## 10. 企业级工作台 UI 优化参考：YonBIP 门户截图

> 本节基于一张 YonBIP 门户首页截图整理，用于支撑 APSPOC 后续主工作台、演示页和产品门户化视觉优化。该参考仅用于 UI 信息架构和视觉组织借鉴，不表示 APSPOC 需要照搬 YonBIP 的产品能力或导航体系。

### 10.1 可借鉴的整体布局

YonBIP 截图呈现的是典型企业级门户工作台：顶部为全局产品导航，左侧为固定图标菜单，中间为业务工作台内容区，右侧为快捷入口与公告信息区。该结构对 APSPOC 后续 UI 优化的启发是：主页面不应只停留在“排程按钮 + Gantt 结果”的单页工具形态，而应逐步演进为一个面向 Planner、Approver、Viewer 和 Admin 的排程工作台。

建议 APS 主工作台采用“固定框架 + 卡片式内容区”的组织方式：

```text
APS 主工作台
├─ 顶部全局栏：项目/环境/当前用户/角色/语言/帮助
├─ 左侧功能栏：导入、场景、排程、版本、审批、审计、设置
├─ 主内容区：当前版本、排程结果、Gantt、异常与差异
└─ 右侧辅助区：快捷操作、公告/提示、最近任务、空态说明
```

该布局可以保留当前 P-02 主工作台的核心功能，同时增强产品感、导航清晰度和演示时的业务叙事能力。

### 10.2 对 APS 主工作台的页面结构建议

参考 YonBIP 的门户卡片布局，APS 主工作台可拆分为以下区域：

1. **顶部导航区**：展示 APS 产品名、当前环境、当前用户、角色、语言切换、帮助入口和退出登录。
2. **左侧功能导航区**：放置导入样本、生成场景、运行排程、版本管理、审批发布、历史审计、系统设置等主入口。
3. **首页摘要区**：展示当前 dataVersion、最近 job 状态、当前版本状态、发布状态、关键 KPI 和待处理事项。
4. **核心工作区**：保留当前 Gantt 结果区，并强化版本摘要、diff、异常任务、资源负荷等入口。
5. **快捷操作区**：放置 Run Schedule、Import / Generate Scenario、Submit Approval、Publish、Rollback、Refresh 等常用动作。
6. **消息与提示区**：展示导入失败、排程失败、审批待办、发布风险、回归状态等系统提示。
7. **空态与引导区**：当尚无 dataVersion、无版本、无 Gantt 数据或无审批任务时，用清晰的引导文案替代空白页面。

### 10.3 视觉风格建议

YonBIP 截图中较值得借鉴的是“企业级、清爽、卡片化”的视觉层次：蓝色顶部栏承载全局导航，浅蓝渐变背景承载页面空间，白色圆角卡片承载业务内容，关键统计信息使用渐变色块强化重点。

APSPOC 后续 UI 优化可采用以下视觉策略：

- **整体背景**：使用浅蓝或浅灰蓝背景，降低纯白页面的单薄感。
- **内容承载**：核心内容统一使用白色圆角卡片，保持卡片间距一致。
- **关键指标**：KPI、版本状态、异常数量、待审批数量可使用高亮统计卡展示。
- **状态颜色**：草稿、待审批、已发布、已归档、失败、冲突等状态应有稳定颜色规范。
- **主次层级**：Gantt 作为主视觉区域，版本摘要、审批状态、异常提醒作为辅助卡片围绕呈现。
- **空态设计**：无数据时使用“暂无版本 / 请先导入样本 / 请先生成场景”等业务化提示，不使用简单空白。

### 10.4 可复用组件拆分建议

如后续基于 React 18 重构或优化 APS 主工作台，建议优先沉淀以下组件：

| 组件 | 用途 | 对应页面 |
| --- | --- | --- |
| `AppShell` | 顶部栏、侧边栏、主内容区整体框架 | P-02 |
| `TopHeader` | 产品名、环境、用户、角色、语言、帮助 | P-02 |
| `SideNav` | 导入、场景、排程、版本、审批、审计等入口 | P-02/P-06/P-08 |
| `WorkspaceCard` | 统一白色圆角卡片容器 | P-02/P-03/P-04 |
| `KpiSummaryCard` | 展示 KPI、版本状态、job 状态 | P-02/P-03 |
| `QuickActionCard` | 常用操作入口 | P-02/P-06/P-08 |
| `StatusNoticeCard` | 系统提示、待办、风险提醒 | P-02/P-08 |
| `EmptyState` | 无数据、无版本、无审批任务等空态 | P-02/P-03/P-04 |
| `TabPanelCard` | 项目/任务类 Tab 卡片，可用于版本、异常、审计分区 | P-03/P-08 |

该拆分方式可以避免 UI 优化只停留在单页样式调整，而是逐步沉淀成可复用的企业级工作台组件库。

### 10.5 对当前 P-02 主工作台的优化落点

结合当前页面地图，优先建议围绕 P-02 主工作台做以下增强：

1. **把当前版本状态前置**：在首屏明显位置展示草稿、待审批、已发布、已归档等状态。
2. **把主链路动作卡片化**：将导入样本、生成场景、运行排程、提交审批、发布和回退做成可见的快捷操作。
3. **把 KPI 与风险摘要卡片化**：将 objective、lateJobs、resourceUtilization、conflictCount 等关键指标以摘要卡展示。
4. **把 Gantt 从单一结果区升级为评审工作区**：周边提供版本差异、异常任务、审计历史、发布说明入口。
5. **把空态做成业务引导**：当无版本或无结果时，引导用户“导入样本 -> 生成场景 -> 运行排程”。
6. **保留当前 MVP 边界**：视觉和信息架构可以优化，但不要把尚未落地的能力写成已实现功能。

### 10.6 React 18 实现建议

若后续进入实现阶段，建议采用 React 18 + CSS Modules 或现有项目样式体系进行重构，不建议为了还原门户视觉而一次性引入大型 UI 重构。

推荐实现顺序：

1. 先实现 `AppShell`，固定顶部栏、侧边栏和主内容区域。
2. 抽象 `WorkspaceCard`，统一卡片圆角、阴影、内边距和标题区。
3. 将当前版本摘要、KPI、操作按钮和 Gantt 区域重新组织到卡片布局中。
4. 补充 `QuickActionCard` 和 `StatusNoticeCard`，承接导入、排程、审批、发布等主链路动作。
5. 最后处理视觉细节，包括背景、间距、状态色、空态插图和 hover/active 效果。

推荐基础布局方向：

```text
AppShell
├─ TopHeader
├─ SideNav
└─ MainWorkspace
   ├─ SummaryRow
   │  ├─ CurrentVersionCard
   │  ├─ KpiSummaryCard
   │  └─ QuickActionCard
   ├─ ReviewWorkspace
   │  ├─ GanttPanel
   │  └─ StatusNoticePanel
   └─ BottomPanels
      ├─ VersionHistoryCard
      └─ AuditAndDiffCard
```

该结构既能借鉴 YonBIP 的企业级门户观感，又能保持 APSPOC 当前“导入 / 场景 / 排程 / 评审 / 审批 / 发布”的业务主链路。
