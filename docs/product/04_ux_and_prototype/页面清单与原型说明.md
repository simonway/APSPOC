> 本文档基于当前前端实际实现整理页面结构，并补充下一阶段 MVP/UAT 需要新增的页面能力。当前系统仍以单页工作台为主，但业务重心将从“样例演示”扩展到“导入真实样本、评审版本、审批发布”。

## 2. 设计原则

- 核心任务优先：围绕“导入/生成场景、排程、评审、审批、发布”组织页面。
- 先稳主流程：优先复用现有工作台与 Gantt，不先做复杂页面重构。
- 结果可解释：版本、KPI、Gantt、差异、异常任务信息要能一起看。
- 治理明确：草稿、待审批、已发布、历史版本需要被用户明显区分。
- 数据可追溯：页面上能看到 dataVersion、jobId、versionId 和关键说明。

## 3. 页面地图

```text
未登录状态
  └─ P-01 登录页
       ├─ 用户名/密码输入
       └─ 中英文切换

已登录状态
  └─ P-02 主工作台
       ├─ 顶部操作区
       │   ├─ 当前用户 / 角色
       │   ├─ Account Settings
       │   ├─ Sign Out
       │   ├─ Run Sample Schedule
       │   ├─ Import / Generate Scenario（MVP 新增）
       │   └─ Refresh Data
       ├─ 左侧版本区（P-03）
       └─ 右侧结果区
           ├─ KPI / 版本摘要
           ├─ 版本治理区（审批/发布/回退）
           ├─ 差异 / 异常任务入口（MVP 增强）
           └─ Gantt 结果区（P-04）

全局弹层/子页面
  ├─ P-05 账号设置弹窗
  ├─ P-06 主数据导入弹窗/页（MVP）
  ├─ P-07 场景生成与导入结果查看（MVP）
  └─ P-08 审批/发布说明区（MVP）
```

## 5. 当前页面详细说明

### P-01 登录页

- 当前目标：登录 + 语言切换。
- 保持不变：左侧视觉区、右侧表单区和错误反馈。
- MVP 增强：可显示登录后角色名称或环境提示（如 UAT 环境）。

### P-02 主工作台

- 当前目标：运行样例、刷新数据、进入版本查看。
- MVP 增强：
  - 顶部区增加 Import / Generate Scenario 入口。
  - 显示当前角色、当前 dataVersion、最近一个 job 状态。
  - 对 Viewer 隐藏创建/审批/发布操作。

### P-03 版本列表与摘要区

- 当前目标：查看版本列表、状态、KPI、基础操作。
- MVP 增强：
  - 显示草稿/待审批/已发布/已归档状态。
  - 增加 diff、history、audit、异常任务入口。
  - 增加 release note、actor attribution 摘要。

### P-04 Gantt 结果区

- 当前目标：查看 Gantt、本地草稿、冲突、试算。
- MVP 增强：
  - 支持按订单/产品/资源/异常任务定位和筛选。
  - 支持展示迟交、固定任务、setup 影响、警告信息。
  - 明确草稿/正式版本边界提示。

### P-05 账号设置弹窗

- 当前目标：修改用户名和密码。
- MVP 增强：角色变化后仅显示当前用户允许的字段；不扩展成完整用户管理后台。

## 6. MVP 新增页面/区域说明

### P-06 主数据导入入口

#### 页面目标

- 让 Planner/Admin 能导入 UAT_v1 样本。

#### 关键内容

- 选择导入对象：Resource、Recipe、Demand、Downtime、SetupRule。
- 上传文件、查看校验结果、下载错误报告。
- 展示 dataVersion、导入人、导入时间。

#### 验收重点

- 错误可定位到 sheet/行/字段。
- 导入失败不会进入排程主流程。

### P-07 场景生成与导入结果

#### 页面目标

- 展示由 dataVersion 生成的场景摘要和转换结果。

#### 关键内容

- 当前 dataVersion。
- Resource/Recipe/Demand/Downtime 数量。
- 生成的 Operation 数量、约束摘要、horizon、目标权重、solver 参数。
- 生成失败原因。

#### 验收重点

- 同一 dataVersion 可复现场景。
- 失败原因可理解。

### P-08 审批/发布说明区

#### 页面目标

- 让版本治理动作更清晰、更可追溯。

#### 关键内容

- release note 编辑。
- 提交审批按钮。
- Approver 的批准/驳回按钮。
- 发布按钮。
- 回退/复制历史版本说明。
- 当前版本的创建人、提交人、审批人、发布人。

#### 验收重点

- 未审批版本不可直接发布。
- 角色按钮显隐和后端权限一致。

## 7. 页面状态要求

| 页面 | 需要具备的状态 |
| --- | --- |
| P-01 | 默认态、提交中、错误态、会话恢复态 |
| P-02 | 默认态、加载态、空态、错误态、任务进行态 |
| P-03 | 无版本态、草稿版、待审批版、已发布版、归档版 |
| P-04 | 无版本态、无行数据态、Clean、Dirty、Conflict、TrialSolving |
| P-06 | 未导入、校验中、校验失败、导入成功 |
| P-07 | 未生成、生成中、生成成功、生成失败 |
| P-08 | 未提交、待审批、已审批、已驳回、已发布 |

## 8. 当前建议的原型补充重点

1. 导入入口与错误报告交互。
2. 版本摘要中 actor attribution 和 release note 的位置。
3. Gantt 上按异常任务定位的交互。
4. 审批/驳回/发布/回退的治理区布局。
5. Viewer 角色下的只读态页面表现。
