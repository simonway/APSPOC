## 2. 使用边界

- 来源材料是视频转写文本，存在少量识别噪音，应作为方向性参考，不作为逐字准确记录。
- 本文档关注“产品页和演示叙事可借鉴什么”，不做竞品优劣评判。
- 文中提到的竞品能力，不应直接写成我方已具备能力；需先映射到我方当前代码与路线图状态。

## 3. 从竞品演示中提炼出的叙事结构

### 3.1 先讲痛点，再讲能力闭环

竞品的开场不是直接展示界面，而是先聚焦工厂计划常见问题：

- Excel 排计划效率低，人工调整成本高
- 订单变化频繁，计划赶不上变化
- 物料、模具、设备、人员等约束相互牵动
- 车间常按“先到先做/好做先做”处理，导致交付与库存失衡
- 生产计划、物料计划、供应协同和执行反馈脱节

对我方产品页的启发：

- 首页首屏不应只写“智能排程”，而应直接点出“计划效率、交付承诺、物料协同、执行闭环”四类问题。
- 要把 APS 讲成“解决工厂计划失真与执行脱节”的系统，而不是单一排程按钮。

### 3.2 竞品最强的不是单点算法，而是全链路闭环

从转写内容看，竞品反复强调的是一条完整业务链路：

1. 销售订单/销售预测进入系统
2. 展开需求与生产需求计划
3. 按工厂能力和综合成本做工厂分配
4. 做物料齐套/物料可得性检查
5. 形成可参与详细排程的生产订单
6. 在详细排程中考虑设备、产线、模具、人员、工序、前后置关系等约束
7. 产出机台级排程、班次计划、订单回复、物料需求、模具需求等报表
8. 接收执行报工/异常反馈，再次调整计划

对我方产品页的启发：

- 必须把“从需求到执行反馈”的链路画出来。
- 产品页结构不能只停留在“导入数据 -> 看甘特图”，而要呈现“需求、计划、约束、排程、执行、回流”的完整叙事。

### 3.3 竞品演示路径高度贴近业务动作

从演示顺序看，竞品非常强调业务动作而不是技术术语：

- 订单需求查看
- 工厂分配
- 物料齐套分析
- 生产订单投放
- 详细排程
- 插单/混排/锁定/滚动排程
- 拖动调整计划
- 多方案比较
- 发布正式排程
- 查看各种报表

对我方产品页和演示页的启发：

- 页面结构应围绕“业务动作清单”组织，而不是按技术模块堆砌。
- 如果后续做产品页二级页或演示页，建议直接用“导入样本 -> 生成场景 -> 运行排程 -> 评审版本 -> 发布/回退 -> 追踪审计”的动作路径。

## 4. 可直接借鉴的产品页信息架构

### 4.1 首页首屏

建议首屏聚焦以下一句话：

> 把订单、物料、产能与执行反馈拉进同一条计划闭环，让工厂从“人工追计划”转为“系统驱动排程与治理”。

首屏建议放 4 个价值点：

- 更快回复交期
- 更稳处理物料与产能约束
- 更清晰评审多版本排程结果
- 更可追溯地发布、回退与审计

### 4.2 第二屏：业务闭环总览

建议用一张主流程图表达：

- 需求输入
- 主数据/场景生成
- 约束与优化
- Gantt 评审
- 版本治理
- 发布与执行反馈

这里要强调“我方的 APSPOC 不是单次试算器，而是带版本治理的排程工作台”。

### 4.3 第三屏：关键能力模块

建议拆成 6 个模块卡片：

1. 需求与样本导入
2. 场景生成与约束准备
3. 排程求解与结果生成
4. Gantt 可视评审与手工调整
5. 版本治理与审批发布
6. 审计历史与回退恢复

每个模块都要写“解决什么业务动作”，不要只写技术对象名。

### 4.4 第四屏：演示路径

建议直接用“5 步演示法”：

1. 导入样本并生成场景
2. 运行排程并生成新版本
3. 在 Gantt 中查看任务、差异与异常
4. 提交审批、批准、发布、回退
5. 查看历史与审计记录

这会比单独强调算法参数更适合产品页。

### 4.5 第五屏：结果与报表

竞品大量强调报表输出。对我方的借鉴不是“报表越多越好”，而是要把输出结果分层：

- 决策层：版本摘要、KPI、交付风险、差异概览
- 计划层：Gantt、任务锁定、异常任务、资源负荷
- 治理层：release note、审批状态、审计历史、回退记录

## 5. 我方产品页建议重点强调的差异化点

相较竞品演示里偏传统 APS 的叙事，我方当前更适合强调以下特点：

- 版本治理是主链路能力，不只是排程结果展示
- 角色边界已明确，有 `Admin / Planner / Approver / Viewer`
- 可以围绕版本 diff、审批、发布、回退来表达“可治理”
- 当前工作台具备较强的 Gantt 评审和差异定位价值
- UAT 样本导入、场景生成与发布 smoke 已形成可验证主链路

因此，我方产品页不应简单照搬“传统 APS 功能树”，而应把以下叙事放到更前面：

- 可验证的版本化排程
- 可审批、可发布、可回退
- 面向 UAT 的真实样本链路
- Gantt + diff + audit 的协同评审

## 6. 对我方后续页面规划的具体建议

### 6.1 需要补强的页面表达

- 在主工作台上更明显地表达“当前版本状态、审批状态、发布状态”。
- 在版本摘要区增加“业务上为什么需要这个版本”的解释性文案空间。
- 对导入/场景生成/排程/发布这条链路，补一层更适合业务看的步骤导航。

### 6.2 产品页应避免的问题

- 不要一上来堆算法名词、目标函数和优化术语。
- 不要把当前尚未产品化的能力包装成“全面工厂中枢”。
- 不要只展示甘特图截图，而没有说明它如何支撑业务动作和治理动作。

### 6.3 建议优先准备的展示素材

- 一张“需求 -> 场景 -> 排程 -> 评审 -> 发布 -> 回退”的闭环图
- 一张当前主工作台全景图
- 一组版本 diff / audit / governance 的界面截图
- 一组 UAT 样本导入与结果页截图
- 一张面向业务价值的 KPI / 风险摘要图
