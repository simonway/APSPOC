## 当前状态补记（2026-05-08）

当前阅读这份文档时，需要明确区分“当前可验态”和“目标态”：

- 当前已落地的是统一登录态和基础版本治理流：`DRAFT -> READY_FOR_RELEASE -> RELEASED / ROLLED_BACK`，并支持 `release note / ready-for-release / publish / rollback / audit`。
- 当前尚未落地的是正式 `Admin / Planner / Approver / Viewer` 角色模型、后端角色权限、正式 `approve / reject` 审批流，以及完整 `QUEUED / TIMEOUT / CANCELLED` 任务状态机。
- 因此本文件中的角色矩阵、目标审批状态、目标任务状态机应理解为“规划目标”，不是当前代码全部已实现的事实。

## 2. 适用范围

- 登录认证与会话。
- 主数据导入、排产任务、版本治理、Gantt 交互、试算。
- 审批、发布、回退和审计。
- 当前不包含企业级组织架构、SSO、多级审批和电子签。

## 3. 当前权限模型

当前已实现权限边界只有两层：

| 用户类型 | 可访问内容 | 限制 |
| --- | --- | --- |
| 未登录用户 | 登录页、认证入口、健康检查、静态资源 | 不可访问业务接口 |
| 已登录用户 | 当前工作台全部能力 | 尚未区分排产员、审批者、只读等角色 |

当前业务接口由会话鉴权保护：除 login、session、logout、health、OPTIONS 外，大多数 `/api/v1/**` 需要登录。

## 4. 当前可验权限与治理口径

当前版本默认按以下口径验收：

- 账号体系：统一登录态，登录后默认拥有当前工作台的全部能力。
- 鉴权边界：未登录不可访问业务接口；已登录可访问当前版本所有业务入口。
- 当前治理流：`DRAFT -> READY_FOR_RELEASE -> RELEASED / ROLLED_BACK`。
- 当前可验证动作：保存 `release note`、提交 `ready-for-release`、`publish`、`rollback`、查看 `history / audit / diff`。

当前不应误表述为已落地能力：

- `Approver / Viewer` 独立账号与权限隔离
- 正式 `approve / reject` 审批动作
- 发布前必须经过独立审批角色的受控流转

## 8. 登录认证状态流转

```text
未认证
  -> 登录成功 -> 已认证
  -> 登录失败 -> 未认证

已认证
  -> 刷新页面且会话有效 -> 已认证
  -> 主动登出 -> 未认证
  -> 会话失效/接口 401 -> 未认证
```

关键规则：

- 前端启动时先检查会话。
- 业务请求返回 401 时，清空本地状态并返回登录页。
- 后续引入角色后，session 需要返回 username 和 role/permissions。

## 9. 排产任务状态流转

### 8.1 当前状态

```text
PENDING
  -> RUNNING
      -> DONE
      -> FAILED
```

### 8.2 MVP/UAT 目标状态

```text
CREATED
  -> QUEUED
      -> RUNNING
          -> SUCCEEDED
          -> FAILED
          -> TIMEOUT
          -> CANCELLED
```

| 状态 | 含义 | 终态 |
| --- | --- | --- |
| CREATED | 后端已创建任务，尚未入队 | 否 |
| QUEUED | 已进入队列，等待执行 | 否 |
| RUNNING | 正在调用 solver 或处理结果 | 否 |
| SUCCEEDED | 求解成功并生成版本 | 是 |
| FAILED | 执行异常或求解失败 | 是 |
| TIMEOUT | 超过允许执行时长 | 是 |
| CANCELLED | 用户或系统取消 | 是 |

关键规则：

- 当前版本至少需要正确处理 `PENDING / RUNNING / DONE / FAILED`。
- 若后续发布额外宣称 `QUEUED / TIMEOUT / CANCELLED`，则前端、接口和文档必须同步验收。
- 每个失败终态都应有 `failureReason`。
- `SUCCEEDED` 必须关联 `versionId`。

## 10. 导入任务状态流转

MVP/UAT 建议增加导入批次状态：

```text
UPLOADED
  -> VALIDATING
      -> VALIDATION_FAILED
      -> VALIDATED
          -> SCENARIO_GENERATED
```

| 状态 | 含义 |
| --- | --- |
| UPLOADED | 文件已上传或数据已提交 |
| VALIDATING | 正在解析和校验 |
| VALIDATION_FAILED | 存在行级/字段级错误 |
| VALIDATED | 数据校验通过，可生成场景 |
| SCENARIO_GENERATED | 已生成排产场景 |

关键规则：

- 校验失败不得进入排程主流程。
- 错误结果需包含 sheet/行/字段/原因。
- 导入成功需记录数据版本。

## 11. 版本状态流转

### 11.1 当前状态口径

当前代码侧已演进出 `DRAFT`、`READY_FOR_RELEASE`、`RELEASED`、`ARCHIVED`、`ROLLED_BACK` 等治理状态。

当前默认可验的业务流是：

```text
DRAFT
  -> READY_FOR_RELEASE
      -> RELEASED
          -> ROLLED_BACK / ARCHIVED
```

说明：

- 当前 `READY_FOR_RELEASE` 代表“提交待发布”的治理中间态。
- 当前并不存在独立 `APPROVED / REJECTED` 状态，也不存在正式 `approve / reject` API。
- 若文档、演示或发布说明中出现“审批通过/驳回”，必须明确其仍属于目标态而非当前实现态。

### 11.2 MVP/UAT 目标业务状态（规划态）

```text
DRAFT
  -> SUBMITTED / READY_FOR_RELEASE
      -> APPROVED
          -> RELEASED
              -> ARCHIVED
              -> ROLLED_BACK
      -> REJECTED
          -> DRAFT
```

| 状态 | 含义 | 可执行动作 |
| --- | --- | --- |
| DRAFT | 求解或试算生成的草稿版本 | 编辑说明、提交审批、删除草稿 |
| SUBMITTED / READY_FOR_RELEASE | 已提交待审批 | 审批、驳回 |
| APPROVED | 审批通过，待发布 | 发布 |
| REJECTED | 审批驳回 | 回到草稿或重新提交 |
| RELEASED | 当前正式发布版本 | 查看、回退、归档 |
| ARCHIVED | 历史归档版本 | 查看、复制为草稿 |
| ROLLED_BACK | 被回退或因回退失效的版本 | 查看、审计 |

### 11.3 发布规则

- 同一时刻最多一个 RELEASED 版本。
- 发布新版本时，当前 RELEASED 应转为 ARCHIVED 或 ROLLED_BACK，取决于业务语义。
- 发布动作必须记录发布人、发布时间、release notes 和前一发布版本。

### 11.4 回退建议语义

MVP 推荐：**复制历史版本形成新草稿，重新审批后发布**。

原因：

- 审计更清晰。
- 可以保留“为什么回退”的 release note。
- 避免直接修改历史版本状态导致业务解释混乱。

## 12. 审批状态流转（规划态）

当前代码尚无正式 `approve / reject` 端点；以下状态流仅用于说明目标产品语义。

```text
未提交
  -> 提交审批 -> 待审批
待审批
  -> 审批通过 -> 已审批
  -> 审批驳回 -> 已驳回
已审批
  -> 发布 -> 已发布
已驳回
  -> 修改/补充说明 -> 未提交
```

审批事件需记录：

- versionId
- 操作人
- 操作类型：SUBMIT / APPROVE / REJECT
- 操作时间
- 评论/意见
- 前后状态

## 13. Gantt 本地草稿状态流转

```text
Clean
  -> 拖拽/调整 -> Dirty
Dirty
  -> 发生重叠 -> Conflict
Dirty
  -> 重置 -> Clean
Dirty
  -> 试算 -> TrialSolving
TrialSolving
  -> 成功生成新 job/version -> Clean 或 NewDraft
  -> 失败 -> Dirty
Conflict
  -> 调整到无冲突 -> Dirty
  -> 重置 -> Clean
```

关键规则：

- 本地草稿不等于正式版本。
- pinned 任务默认不可拖拽，除非通过明确解锁/试算流程。
- 试算成功应生成新的 job/version 或明确结果，不直接覆盖已发布版本。

## 16. 当前实现限制

- 当前代码虽已有版本治理基础，但角色权限仍需补齐。
- 当前任务状态仍以 `PENDING / RUNNING / DONE / FAILED` 为主，未形成完整队列态和取消/超时语义。
- 当前部分状态名与业务目标状态存在命名差异，需要在接口契约中统一映射。
- 当前 `READY_FOR_RELEASE` 不能被误解为“完整审批通过”。
- 回退语义需要产品/业务/研发最终确认。
- Gantt 本地草稿仍需持续提示“未保存、非正式”。
