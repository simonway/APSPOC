## 2. 目标与适用范围

本清单只适用于第三期主链路相关回归：

- `snow_beer_main_chain_phase3` 样本的场景生成、求解和 Gantt smoke
- backend / solver / frontend 静态检查中的第三期最低保障项

本清单不定义第四期全场景回归全集，也不替代第五期正式 release gate。

## 4. 当前最小回归命令集

第三期当前建议最小回归基线如下：

### 4.1 静态与单元测试基线

```bash
rtk mvn test
rtk python3 -m unittest discover -s solver/tests -p 'test_*.py'
rtk node --check backend/src/main/resources/static/app.js
```

### 4.2 第三期样本校验基线

```bash
rtk python3 scripts/build_uat_sample_package.py docs/sample-packages/snow_beer_main_chain_phase3 --check
rtk python3 scripts/uat_package_smoke.py docs/sample-packages/snow_beer_main_chain_phase3
```

### 4.3 当前默认发布回归现状

```bash
rtk bash scripts/verify-release.sh
```

说明：

1. 当前 `verify-release.sh` 已显式覆盖 `phase3` 主链路 smoke。
2. 当前 `uat_package_smoke.py` 默认目录也已切到 `phase3`，避免继续依赖旧样本默认值。
3. 若要校验其他样本，应显式传入对应目录，避免误用第三期默认入口。

## 7. 默认回归策略建议

建议把第三期默认回归分成两层：

### 7.1 短期策略

第三期正式收口前，至少保证：

1. 日常回归继续使用现有 `verify-release.sh`，因为它已默认覆盖 `phase3` smoke。
2. 任何涉及场景生成、solver、Gantt 或样本语义的改动，仍建议额外执行一次显式 `phase3` smoke。
3. 对外演示前，仍建议执行 `build_uat_sample_package.py --check` 和显式 `phase3` smoke。

### 7.2 中期策略

第三期准备宣布正式完成前，应至少落定以下一项：

1. 在 `verify-release.sh` 中显式增加 `docs/sample-packages/snow_beer_main_chain_phase3` smoke。
2. 或者新增单独的第三期主链路默认 smoke 入口，并把它纳入 release 回归标准。

不建议继续依赖“脚本默认值碰巧覆盖到第三期”的隐式方式。

## 8. 完成判定

只有同时满足以下条件，才建议判定 `WP-E` 通过：

1. 第三期主链路最小回归命令集已冻结并被团队接受。
2. `phase3` 样本 smoke 已进入默认回归主路径，或已有等价固定入口。
3. backend / solver 至少各有一条与第三期主链路直接相关的稳定自动化证据。
4. `setup/changeover` 与主要失败口径的缺口已有明确补强计划或已补齐。
5. 后续改动如破坏第三期主链路，能够在默认回归中尽早暴露。
