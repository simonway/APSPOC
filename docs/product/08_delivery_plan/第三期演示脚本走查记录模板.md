## 3. 走查目标

本次走查至少应确认以下目标：

1. 产品或售前能不依赖研发口头补充，按固定脚本完成一轮主链路演示。
2. 开场定位、步骤顺序、结果讲解和范围边界没有口径冲突。
3. README 中列出的关键证据点都能被稳定展示和解释。
4. 如出现失败场景，演示人知道应引用 `第三期基础不可行解释口径表.md` 进行解释。
5. 走查后可以明确当前脚本是“通过”“有条件通过”还是“需重写”。

## 4. 走查通过标准

只有同时满足以下条件，才建议判定本轮走查通过：

1. 演示主流程可顺序完成，不出现步骤缺失或明显卡顿。
2. `12` 个任务、`9` 条 precedence、库存覆盖、插单优先级、停机、换型等证据点可被讲清楚。
3. 第三期、第四期、第五期边界能被明确讲出，不出现越界承诺。
4. 演示人可以独立回答“为什么现在能演示”“为什么这些规则留到后续阶段”。
5. 走查中提出的问题都已记录为明确动作项。
