# 第四期发酵罐规则建模草案

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v0.1 |
| 当前状态 | 首版规则草案 |
| 适用阶段 | Snow Beer 第四期 |
| 更新时间 | 2026-07-01 |
| 相关样本 | `snow_beer_phase4_maturity_window`、后续 `snow_beer_phase4_fermentation_tank` |

> 本文档只冻结发酵罐容量、占用和不可混装的第一版规则语义，不声明当前系统已经精确支持这些规则。

## 2. 规则目标

第四期发酵罐规则要回答三类业务问题：

1. 罐体容量是否足够承接当前批次。
2. 罐体在发酵和成熟占用窗口内是否可用。
3. 同一罐体是否允许混装不同产品族、批次或状态。

## 3. 支持状态分层

### 3.1 Exact support

当前可作为精确能力依赖的范围很窄：

| 能力 | 当前语义 | 证据/边界 |
| --- | --- | --- |
| 发酵离散任务 | `FERMENTATION` 可作为一段普通生产任务进入生成和排程 | Phase 3 主链样本已覆盖 `SUGARIZATION -> FERMENTATION -> FILTRATION -> PACKAGING` |
| 单任务资源占用 | 发酵任务在自身开始到结束时间内占用候选资源 | 只覆盖任务时段，不覆盖任务结束后的成熟驻留 |
| 任务前后置 | 下游任务可通过 precedence 等待上游任务完成 | 可表达顺序，不等价于罐体持续占用 |

### 3.2 POC approximation

当前第四期首批样本只能把部分业务概念做成可审计的近似：

| 能力 | POC 表达 | 不覆盖内容 |
| --- | --- | --- |
| 成熟等待 | `MATURATION_WAIT` 代理操作放在发酵和过滤之间 | 不表示真实发酵罐继续被占用 |
| 成熟释放点 | 通过代理操作结束时间表达最早可过滤点 | 不校验罐释放、转罐、取样或质量放行 |
| 容量单位 | 文档先定义 `tankCapacityUnits` 代理 lot 单位 | 当前 solver 不累计同一罐窗口内的容量占用 |
| 产品族兼容性 | 先用产品族/setup group 作为不可混装判断词汇 | 当前 setup rule 不表达同罐驻留期混装约束 |

### 3.3 Deferred

以下能力必须作为后续 backend/solver/sample contract 切片，不在首批样本中声明完成：

| 能力 | 延后原因 |
| --- | --- |
| 发酵罐真实容量计算 | 需要统一 KL、批量、代理 lot 和配方产出之间的换算关系 |
| 跨操作占用窗口 | 需要 solver 支持一个批次在发酵完成后继续占用同一罐直到释放点 |
| 同罐不可混装 | 需要在同一 occupation window 内检查产品族、批次、状态兼容性 |
| 多锅次满罐 | 需要定义多个糖化/发酵批次如何聚合为一个罐占用 |
| 亮啤罐转移、后熟、鲜度窗口 | 与发酵罐释放点相关，但属于后续更完整的啤酒工艺链 |
| 失败原因结构化解释 | 需要从 solver 不可行结果映射到业务可读原因 |

## 4. 第一版建模词汇

| 概念 | 建议字段 / 来源 | 业务含义 | 第一版建议 |
| --- | --- | --- | --- |
| `tankId` | resource id | 发酵罐资源编号 | 沿用 `02_resources.csv.id` |
| `tankCapacityUnits` | future rule file | 罐体可承接的代理 lot 单位 | 先用整数代理单位，后续再映射 KL |
| `batchVolumeUnits` | future rule file or demand extension | 当前批次占用代理单位 | 先固定为每 lot 1 单位 |
| `occupationStart` | generated fermentation start | 罐体占用开始 | 取发酵任务开始 |
| `occupationEnd` | generated maturity release | 罐体释放时间 | 精确模型应覆盖成熟完成或释放点 |
| `mixingFamily` | product family / setup group | 不可混装兼容性 | 第一版按产品族判断 |
| `batchId` | generated operation or future batch field | 同一生产批次标识 | 用于解释同罐占用冲突 |
| `releaseReason` | future explain field | 罐体释放依据 | 可取成熟完成、质量放行、转罐完成等 |

## 5. 第一版规则语义

### 5.1 Tank capacity unit

首版不直接使用 KL 做硬约束，先使用代理 lot 单位：

- `tankCapacityUnits` 表示一个发酵罐在同一占用窗口内最多可承接的代理批量。
- `batchVolumeUnits` 表示一个批次消耗的代理容量，首版默认每个 demand lot 为 1。
- 成功条件是同一罐、同一 occupation window 内的 `batchVolumeUnits` 总和不超过 `tankCapacityUnits`。
- KL、吨、锅次、浓度和损耗换算进入后续 refinement，不能在首版样本中假装已经精确。

### 5.2 Occupation window

发酵罐占用窗口应从发酵开始持续到可释放点：

- `occupationStart` 取发酵任务实际开始时间。
- `occupationEnd` 在精确模型中应取成熟完成、质量放行或转罐完成后的释放点。
- `MATURATION_WAIT` 当前只是成熟等待的 POC 代理，可用于说明过滤不能过早开始。
- `MATURATION_WAIT` 不等价于真实罐占用，因为当前资源占用仍只落在单个任务自身时段内。

后续 solver 需要支持跨操作资源占用：发酵操作结束后，罐体仍被该批次占用，直到 `occupationEnd`。

### 5.3 Non-mixing

同一占用窗口内，同一罐体不能混装不兼容产品族或批次状态：

- 第一版按 `mixingFamily` 判断兼容性，例如 A500 与 B600 默认不兼容。
- 同一 `mixingFamily` 是否允许合罐，需要另行定义批次状态、清洗状态和质量规则。
- setup group 只能作为第一版兼容性来源之一，不能替代同罐驻留期规则。
- 如果一个候选罐在目标 occupation window 内已有不兼容批次，应判定该候选罐不可用。

## 6. 失败解释口径

| 失败类型 | 面向业务的解释 | 技术定位 |
| --- | --- | --- |
| 无可用罐 | 当前候选发酵罐在所需占用窗口内均已被占用 | 所有候选 `tankId` 的 occupation window 冲突 |
| 容量不足 | 可用罐容量不足以承接当前批次 | `sum(batchVolumeUnits) > tankCapacityUnits` |
| 不可混装 | 候选罐中已有不兼容产品族或批次状态 | `mixingFamily` 或批次状态不兼容 |
| 成熟释放冲突 | 批次尚未达到释放条件，不能进入下游 | `occupationEnd` 晚于下游最早开始需求 |
| 字段缺失 | 样本或导入数据缺少罐规则所需字段 | rule file/import validation 失败 |

失败解释应面向业务给出“为什么不能排”，而不是只返回 solver infeasible。首版后续样本至少要能把失败落到上述一种主因。

## 7. 未来成功/失败样本形态

后续 `snow_beer_phase4_fermentation_tank` 应拆成可审计的小样本，而不是一次性覆盖所有啤酒工艺。

### 7.1 成功样本

成功样本建议包含：

- A500 与 B600 各 1 个批次，候选罐不同，最终分配到不同 `tankId`。
- 或 A500 与 B600 使用同一候选罐集合，但 occupation window 不重叠。
- 每个批次都有明确 `tankCapacityUnits`、`batchVolumeUnits`、`mixingFamily` 和释放点。
- expected checks 验证没有容量超限、没有窗口重叠、没有不兼容混装。

### 7.2 容量失败样本

容量失败样本建议包含：

- 单一产品族，避免把失败原因混入不可混装。
- 候选罐可用，但 `batchVolumeUnits` 超过所有候选罐的 `tankCapacityUnits`。
- expected checks 明确主因是容量不足，不是无可用罐。

### 7.3 不可混装失败样本

不可混装失败样本建议包含：

- A500 与 B600 被迫争用同一发酵罐和重叠 occupation window。
- 单罐容量足够，避免把失败原因混入容量不足。
- expected checks 明确主因是 incompatible mixing family。

### 7.4 占用窗口失败样本

占用窗口失败样本建议包含：

- 同一产品族、容量足够。
- 失败只来自成熟释放点过晚，导致目标罐在下一个批次需要开始时仍未释放。
- expected checks 验证冲突窗口来自 `occupationStart` 到 `occupationEnd`，不是单个发酵任务时段。

## 8. 需要后续扩展的系统点

| 区域 | 需要扩展 |
| --- | --- |
| 样本契约 | 新增规则文件或扩展资源/配方字段表达容量、批量、产品族和释放点 |
| backend import | 校验罐规则字段、产品族兼容性和容量单位 |
| scenario generation | 将罐规则绑定到生成任务、物料流、批次和候选资源 |
| solver | 支持跨操作占用窗口、容量累计和不可混装约束 |
| Gantt / explain | 展示罐占用、释放点和失败原因 |
| UAT expected checks | 区分容量、窗口、不可混装和数据字段缺失四类验证 |

## 9. 当前结论

第一批 Phase 4 只提交规则草案，不把发酵罐容量、占用和不可混装写成已实现能力。等 material availability 和 maturity-window POC 样本稳定后，再单独开 `snow_beer_phase4_fermentation_tank` 实施切片。
