## 2. 规划原则

1. 每个 P0 场景都必须有可追溯样本目录。
2. 每个样本目录都必须至少有 README、expected checks 和可重跑入口。
3. 每个 P0 场景都建议同时准备成功样本或失败样本。
4. 每个样本都必须能映射到 backend、solver 和 smoke 至少一条自动化入口。

## 5. 自动化回归矩阵

| 层级 | 目标 | 当前入口 / 建议入口 | 第四期要求 |
| --- | --- | --- | --- |
| 样本构建校验 | 样本文件完整且可生成 | `python3 scripts/build_uat_sample_package.py <dir> --check` | 每个样本包必须接入 |
| backend 场景生成 | 复杂场景能展开为正确 operation / precedence / material 流 | `ScenarioGenerationServiceTest` 或新增同类测试 | 每个 P0 场景至少 1 条 |
| solver 回归 | 复杂规则能求解或返回业务化失败原因 | `solver/tests/test_solver_service.py` 扩展 | 每个 P0 场景至少 1 条 |
| 样本 smoke | 导入、场景生成、排程、Gantt 链路可重复运行 | `python3 scripts/uat_package_smoke.py <dir>` | 每个 P0 场景至少 1 条 |
| 组合 smoke | 主链路与复杂场景可以一起跑 | 新增 `phase4_full_suite` 组合样本 | 第四期末必须具备 |
| UI 走查 | 产品 / 售前可解释复杂场景结果 | README + 人工走查记录 | 至少覆盖综合样本 |

## 6. 验收证据要求

| 编号 | 证据要求 | 说明 |
| --- | --- | --- |
| `P4-EV-01` | 每个 P0 样本目录都有 README | 要写明业务语义、近似边界和演示口径 |
| `P4-EV-02` | 每个 P0 样本都有 expected checks | 至少写明任务数、关键前后置、关键物料或窗口结果 |
| `P4-EV-03` | 每个 P0 场景都有自动化入口 | backend / solver / smoke 至少覆盖其中两类 |
| `P4-EV-04` | 每个 P0 场景都有业务化失败解释 | 失败时不能只暴露技术枚举 |
| `P4-EV-05` | 组合样本能证明主链路未被复杂规则改坏 | `phase3` 与 `phase4_full_suite` 需要并行维护 |

## 7. 变更控制规则

1. 新增第四期样本目录时，必须同步更新本清单。
2. 样本如果采用 POC 近似，必须把近似边界写进 README。
3. 改动任何第四期样本时，至少执行对应 build check 和一条自动化入口。
4. `phase3` 主链路样本仍保留为基线，不允许被第四期样本替代。

## 8. 当前建议下一步

1. 先创建 `snow_beer_phase4_maturity_window`、`snow_beer_phase4_fermentation_tank`、`snow_beer_phase4_bright_tank_transfer` 三个首批目录。
2. 首批目录创建后，优先补 backend 场景生成测试和 solver 失败解释测试。
3. 等首批 P0 场景稳定后，再组装 `snow_beer_phase4_full_suite` 作为第四期组合回归入口。
