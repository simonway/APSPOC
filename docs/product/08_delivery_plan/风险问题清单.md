## 4. 当前 Top 风险

### Top 1：试点范围与样本冻结失败（R-01 / R-02 / R-03）

- 现象：没有稳定的试点边界和样本，后续导入、solver、UAT 都没有统一标尺。
- 影响：直接阻断从演示到 UAT 的所有工作包。
- 当前建议：把 M0 冻结会作为立即动作，确认试点范围、样本责任人、冻结日期和字段口径。

### Top 2：Must 约束复杂度超预期（R-04 / R-05）

- 现象：业务希望结果贴近真实排产，但 precedence、setup、需求展开可能远比预期复杂。
- 影响：结果即使能求解，也可能不被业务接受。
- 当前建议：只覆盖试点 Must 约束；Should/Could 进入 backlog，不阻塞 MVP。

### Top 3：执行稳定性与性能不足（R-06 / R-07）

- 现象：真实数据规模下可能出现求解慢、状态丢失、长任务失败难定位等问题。
- 影响：UAT 期间用户体验和可信度显著下降。
- 当前建议：在 M4 前定义性能门槛、状态机和观测口径，必要时升级队列方案。

### Top 4：版本治理与角色权限不清（R-08 / R-09 / R-10）

- 现象：审批、发布、回退和草稿语义混淆，容易造成业务误解或审计风险。
- 影响：业务不敢采用系统输出作为正式计划依据。
- 当前建议：在 M5 前冻结状态机、角色边界和 audit 字段。

## 7. 风险复盘机制建议

- 每周例会检查一次 Top 风险状态和新增风险。
- 每个里程碑结束后更新风险总表、状态和应对动作。
- 高影响高概率风险必须绑定负责人和下一个明确动作。
- 已关闭风险保留关闭依据，避免后续重复发生认知偏差。
