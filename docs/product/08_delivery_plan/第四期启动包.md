## 2. 第四期目标

第四期目标不是再证明第三期主链路能跑，而是补齐 Snow Beer POC 复杂业务场景，使系统能回答：

1. 复杂业务场景是否有明确样本。
2. 复杂业务场景是否能排程、近似排程或被明确解释为后置。
3. 每个场景的结果和失败原因是否能用业务语言解释。
4. 主链路样本与复杂场景样本是否能一起进入可重复回归。

## 3. 第四期范围边界

### 3.1 纳入第四期

- 发酵成熟窗口。
- 发酵罐容量、占用、不可混装。
- 多锅次与满罐关系。
- 过滤到清酒转换、清酒罐中转。
- 静置 / 保鲜窗口。
- 物料可用时间与缺料解释。
- 复杂场景样本、业务解释和全场景回归。

### 3.2 不纳入第四期开工最小范围

- 发布级性能基线。
- 队列、超时、取消 / 重试、完整状态机。
- 正式审批治理、角色权限矩阵和 release gate。
- UI 视觉与交互 polish。

### 3.3 默认继续后置，除非另行升级优先级

- 连续流。
- 浓度 / 收率精确机理。
- 采购计划自动反推。

## 8. 开工必须决策项

| 编号 | 决策项 | 默认建议 | 原因 |
| --- | --- | --- | --- |
| `P4-DEC-01` | 发酵成熟窗口是硬约束、软约束还是分层约束 | 先做“最早可过滤 / 最晚建议窗口”的分层表达 | 兼顾演示可解释性与实现复杂度 |
| `P4-DEC-02` | 发酵罐容量与不可混装是否要求精确支持 | 容量 / 占用 / 不可混装先做最小精确支持 | 这是第四期最容易影响业务可信度的规则 |
| `P4-DEC-03` | 多锅次与满罐关系是否允许 POC 近似 | 允许，但必须写清近似边界 | 避免在第四期过早陷入机理级建模 |
| `P4-DEC-04` | 连续流、浓度 / 收率是否纳入第四期开工最小范围 | 默认继续后置 | 防止第四期开工即失焦 |
| `P4-DEC-05` | 第四期首批样本数据源 | 先基于当前 Snow Beer 脱敏样本扩展 | 保持与第三期证据链连续 |

## 9. 第四期开工会输出要求

开工会至少输出以下结果：

1. 第四期复杂场景优先级表。
2. 每个场景的精确支持 / POC 近似 / 后置结论。
3. 首批样本包目录和负责人。
4. backend / solver / smoke / UI 走查四条验证入口。
5. 本阶段不做事项和对外话术边界。

## 10. 当前建议下一步

1. 先按 `第四期复杂场景清单.md` 逐项冻结场景和建模边界。
2. 再按 `第四期样本与回归规划清单.md` 建立首批样本目录与自动化入口。
3. 每个 P0 场景都要求同时准备“成功样本”或“可解释失败样本”。
4. 对连续流、浓度 / 收率、采购反推保持单独记录，不默认混入第四期开工最小范围。
