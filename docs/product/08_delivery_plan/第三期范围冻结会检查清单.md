> 本清单用于支撑 Snow Beer 第三期范围冻结会，确保会议能一次性确认第三期正式演示边界、输出结论并形成留痕。

## 2. 会议目标

本次范围冻结会应完成以下目标：

1. 确认第三期正式演示到底演示什么。
2. 确认哪些内容明确不属于第三期，不得在第三期对外承诺。
3. 确认当前 `snow_beer_main_chain_phase3` 样本是否足以作为第三期正式样本基线。
4. 确认第三期验收与演示口径是否统一。
5. 输出一份可留痕的冻结结论，作为后续演示、收口和第四期输入依据。

## 3. 参会角色建议

建议至少包含以下角色：

| 角色 | 是否必须 | 主要职责 |
| --- | --- | --- |
| 产品负责人 | 必须 | 主持范围确认、记录结论 |
| 业务代表 | 必须 | 确认业务主链路是否成立 |
| 售前/演示负责人 | 必须 | 确认演示脚本和对外话术 |
| 研发代表 | 必须 | 确认当前实现边界和可回归性 |
| 算法/求解代表 | 建议 | 确认建模边界和不可行解释 |
| 测试/UAT 代表 | 建议 | 确认验收口径和证据要求 |
| 项目负责人 | 建议 | 确认阶段结论和下一步动作 |

会议开始前，应准备好以下材料：

| 材料 | 是否必须 | 用途 |

| `第三期正式演示范围清单.md` | 必须 | 作为本次冻结会主依据 |

| 当前 smoke 或回归结果 | 建议 | 证明第三期样本当前可运行 |
| 第四期/第五期边界说明 | 建议 | 避免会上混入后续诉求 |

建议会前先把以下事实同步给参会人：

- 当前第三期已经完成第一轮技术闭环，但还未正式收口。
- 本次会议不是讨论第四期复杂行业规则设计细节。
- 本次会议也不是讨论第五期发布级性能和正式 release 门禁。

## 5. 会议议程建议

建议按以下顺序开会：

1. 说明本次会议目标和输出物。
2. 快速回顾第三期当前已完成证据。
3. 逐项确认第三期必须演示内容。
4. 逐项确认第三期明确不演示内容。
5. 确认当前样本和脚本是否满足第三期基线。
6. 确认是否还有必须纳入第三期但当前缺失的内容。
7. 形成冻结结论、责任人和后续动作。

## 8. 会后动作清单

会议结束后，应立即执行以下动作：

1. 使用 `第三期范围冻结会会议纪要模板.md` 形成正式会议纪要。
2. 将本次会议纪要中的最终结论回写到 `第三期正式演示范围清单.md`。
3. 如范围已冻结，将文档状态从“待确认稿”升级为“正式冻结版”。
4. 将仍未完成的事项回写到 `第三期收口计划.md`。
5. 如有第四期输入问题，转入第四期范围或风险清单。
6. 将会议纪要同步给产品、售前、研发、算法、测试。

## 9. 本次会议通过标准

只有同时满足以下条件，才建议判定本次范围冻结会通过：

1. 第三期必须演示内容已逐项确认。
2. 第三期明确不演示内容已逐项确认。
3. 当前样本基线已被接受。
4. 当前话术边界已被接受。
5. 仍需补做事项已形成责任人与后续动作。

1. 先用本清单开会，不要直接在会议中临时口头讨论范围。

3. 然后回写 `第三期正式演示范围清单.md`，形成正式冻结版。
