> 本文档用于把第三期中的 `INFEASIBLE`、失败提示和基础不可行场景，从技术现象沉淀为业务可理解口径，供演示、验收和问题解释统一使用。

## 2. 适用范围

本口径表只适用于第三期正式演示和第三期验收：

- Snow Beer 主链路离散排程演示。
- 当前 `snow_beer_main_chain_phase3` 及其相邻失败验证场景。
- 第三期明确承诺的四类基础失败解释：
  - 产能不足
  - 物料不足
  - 窗口冲突
  - 无可用资源

本口径表不用于解释第四期复杂酿造规则，也不用于代替第五期发布级异常治理方案。

## 3. 使用原则

第三期解释失败场景时，统一遵循以下原则：

1. 先说业务现象，再说当前系统判断，最后再说建议动作。
2. 不把导入错误、主数据引用错误、非法请求直接说成“排程不可行”。
3. 若系统只是给出延期或明显产能紧张结果，不强行解释为 `INFEASIBLE`。
4. 若同一场景存在多个可能原因，优先解释当前阻断主链路的第一原因。
5. 若根因依赖第四期复杂规则才能进一步细分，必须明确说明“该细分规则不在第三期建模范围内”。

## 4. 当前统一分类

| 分类编号 | 失败类型 | 第三期统一定义 | 当前对外关键词 |
| --- | --- | --- | --- |
| P3-IF-01 | 产能不足 | 当前可用资源、时长、停机和时间窗口组合下，无法在要求范围内承载本轮需求 | 当前可用产能不足 |
| P3-IF-02 | 物料不足 | 原料、包材、中间物料或库存覆盖条件不足，导致任务无法成立 | 当前物料不足 |
| P3-IF-03 | 窗口冲突 | 资源停机、物料可用时点、固定窗口或其他时间条件与需求窗口冲突 | 当前时间窗口冲突 |
| P3-IF-04 | 无可用资源 | 当前工序没有可用候选资源，或现有候选资源无法形成有效执行路径 | 当前无可用设备/资源 |

## 5. 分类明细口径

### 5.1 P3-IF-01 产能不足

| 项目 | 口径 |
| --- | --- |
| 典型触发条件 | 当前资源总可用时长不足、可用资源过少、停机占用过多，导致本轮需求在目标窗口内无法承载 |
| 当前系统可能表现 | 可能表现为 `INFEASIBLE`，也可能表现为可排但明显延期；第三期应先区分“完全不可排”与“可排但产能紧张” |
| 业务解释建议 | 当前这批需求在现有设备与时间条件下，产能承载不够，系统无法给出满足当前要求的排程结果，或只能给出明显延期的结果 |
| 建议对外说法 | 可以说：当前资源负荷和时间窗口不足以承接本轮需求，需要增加可用产能、放宽时间窗口或调整需求优先级 |
| 不应这样说 | 不应直接说“系统算不出来”；也不应把延期结果误说成模型失效 |
| 当前证据状态 | 已有贴近第三期样本的专项 solver 回归证据 |
| 当前证据来源 | `solver/tests/test_solver_service.py` 中的 `test_snow_beer_packaging_capacity_shortage_is_infeasible` |

### 5.2 P3-IF-02 物料不足

| 项目 | 口径 |
| --- | --- |
| 典型触发条件 | 原料不足、包材不足、成品库存覆盖不够、中间物料没有按时产出 |
| 当前系统可能表现 | `INFEASIBLE`，且 `scheduledTasks` 为空；也可能在导入阶段就因输入不完整被拦截 |
| 业务解释建议 | 当前不是设备排不过去，而是这批需求缺少必要物料，主链路任务无法成立，所以系统不给出可执行排程 |
| 建议对外说法 | 可以说：当前库存或包材条件不满足，系统识别到物料无法齐套，因此本轮排程不能成立 |
| 不应这样说 | 不应把物料不足解释成第四期复杂工艺规则缺失 |
| 当前证据状态 | 已有自动化回归证据 |
| 当前证据来源 | `solver/tests/test_solver_service.py` 中的 `test_raw_material_shortage_makes_request_infeasible`、`test_snow_beer_packaging_material_shortage_is_infeasible` |

### 5.3 P3-IF-03 窗口冲突

| 项目 | 口径 |
| --- | --- |
| 典型触发条件 | 物料可用时点晚于需求窗口、停机窗口压住关键资源、固定窗口与任务时长冲突 |
| 当前系统可能表现 | 可能表现为 `INFEASIBLE`，也可能表现为任务被迫后移；第三期应重点说明“窗口约束已生效” |
| 业务解释建议 | 当前不是工艺路径不存在，而是关键时间条件互相冲突，例如物料晚到、设备在关键时段停机，导致这轮需求无法在当前窗口内完成 |
| 建议对外说法 | 可以说：系统识别到时间窗口互相冲突，当前安排下没有满足条件的排程方案 |
| 不应这样说 | 不应把所有时间问题都归类为产能不足；也不应提前承诺第四期成熟窗口等精细规则已支持 |
| 当前证据状态 | 已有贴近第三期样本的专项 solver 回归证据 |
| 当前证据来源 | `solver/tests/test_solver_service.py` 中的 `test_inventory_balance_available_after_due_can_make_job_infeasible`、`test_snow_beer_packaging_downtime_window_conflict_is_infeasible` |

### 5.4 P3-IF-04 无可用资源

| 项目 | 口径 |
| --- | --- |
| 典型触发条件 | 某工序没有候选资源、候选资源引用错误、或当前候选资源集合在现有窗口内无法提供可执行路径 |
| 当前系统可能表现 | 若资源引用错误，通常应表现为导入/场景校验失败，而不是 `INFEASIBLE`；若资源存在但不可用，才应解释为业务上的“无可用资源” |
| 业务解释建议 | 当前这道工序没有可用设备可以承接，或者当前配置下没有有效资源路径，因此系统无法继续排程 |
| 建议对外说法 | 可以说：当前任务缺少可执行设备或资源路径，需要先补齐资源配置或调整资源可用性 |
| 不应这样说 | 不应把“主数据错误”与“业务资源紧张”混为一谈 |
| 当前证据状态 | 已有贴近第三期样本的专项校验回归证据 |
| 当前证据来源 | `docs/product/03_requirements/非功能需求.md` 中“该需求无可用设备”的用户可理解示例；`solver/tests/test_solver_service.py` 中的 `test_snow_beer_packaging_without_candidate_resource_is_rejected`、`test_unknown_downtime_resource_is_rejected` |

## 6. 技术状态到业务口径的映射

| 技术现象 | 第三期推荐业务解释 | 备注 |
| --- | --- | --- |
| `INFEASIBLE` 且物料相关输入不足 | 优先解释为物料不足 | 不要先说 solver 异常 |
| `INFEASIBLE` 且关键时点/停机窗口冲突明显 | 优先解释为窗口冲突 | 说明哪个窗口先阻断 |
| 明显延期但仍有排程结果 | 优先解释为产能紧张或当前窗口不足 | 不强行说不可行 |
| 资源引用错误、无候选资源 | 优先解释为资源配置缺失或无可用设备 | 更接近 `INVALID_SCENARIO` 或导入校验问题 |
| 无法进一步细分到成熟窗口、清酒罐规则等 | 明确说明该细分规则不在第三期建模范围 | 避免越界承诺 |

## 7. 演示与验收推荐说法

| 场景 | 推荐说法 | 不推荐说法 |
| --- | --- | --- |
| 物料不足 | 当前这轮需求缺少必要物料或包材，系统因此不给出可执行排程结果 | 算法坏了 / 系统没有排出来 |
| 窗口冲突 | 当前关键时间窗口互相冲突，例如物料晚到或设备停机压住了关键工序 | 这条链路做不了，原因不清楚 |
| 产能不足 | 当前可用产能不足以在要求窗口内承接这轮需求，需要调整容量、时窗或优先级 | 设备太少所以系统失灵 |
| 无可用资源 | 当前工序没有可承接的设备或资源路径，需要先补齐资源配置 | 这个工序系统不支持 |

## 8. 与第三/四/五期边界的关系

以下解释边界必须明确：

- 若问题本质上需要成熟窗口、罐体占用、不可混装、清酒罐中转、静置/保鲜等规则才能进一步细分，只能说明这是第四期问题，不得倒推成第三期已承诺能力。
- 若问题本质上是性能、超时、审批流、发布治理或 UI 可读性，则归到第五期产品化问题，不纳入第三期基础不可行解释完成定义。
- 第三期的目标是“主链路可演示、基础失败可解释”，不是“所有业务失败都已精细分类”。
