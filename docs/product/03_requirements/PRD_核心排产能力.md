## 2. 背景与目标

- 背景：当前系统已完成从登录、发起样例排产、异步轮询任务、生成版本、查看甘特图到发布版本的基础闭环，并提供了通用排产任务 API。
- 要解决的问题：验证排产主链路能否在一个统一工作台中完成，验证多资源分配、停机窗口避让、版本沉淀和结果可视化的可行性。
- 本文档覆盖的能力边界：覆盖“登录进入系统 → 发起排产 → 查看任务状态 → 查看版本与 Gantt → 发布版本”的核心流程；对于“真实业务建模、版本 diff、完整回滚审计、高级 APS 约束”只定义为后续需求。

## 3. 目标用户

| 用户角色 | 使用场景 | 核心诉求 | 使用频率 |
| --- | --- | --- | --- |
| 排产员 | 发起排产、查看结果、选择发布版本 | 快速生成方案并能看懂结果 | 高 |
| 生产管理 | 查看 KPI、确认当前方案是否可发布 | 快速判断方案优劣和状态 | 中 |

## 5. 功能范围

### 5.1 本期功能

- 登录、登出、会话校验、账号设置、中英双语切换。
- 样例排产任务提交。
- 通用排产任务提交 API。
- 排产任务状态轮询与失败反馈。
- 版本列表、版本详情、KPI 展示、Gantt 展示。
- 版本发布。
- Gantt 的缩放、图例、详情、本地草稿拖拽和冲突提示。

### 5.2 后续阶段功能

- 面向业务用户的真实建模页面。
- 调整后重新求解并生成新版本。
- 版本 diff、发布历史、完整回滚审计。
- 主数据导入与外部系统集成。
- Redis 队列化执行和更大规模调度。
- 换型、工艺前后置、库存/物料等高级 APS 约束。

### 6.2 单项需求说明

#### FR-001 登录与会话管理

- 业务目标：确保工作台和排产版本仅对已登录用户开放。
- 触发条件：用户首次打开系统、刷新页面、会话失效、主动登出、修改账号。
- 前置条件：系统服务可用，存在合法账号。
- 主要流程：
  1. 用户进入系统时先检查会话。
  2. 未登录则展示登录页。
  3. 登录成功后进入主工作台并刷新版本数据。
  4. 会话失效时清理前端状态并回到登录页。
- 异常流程：账号密码错误、服务不可达、当前密码错误、密码长度不满足要求。
- 输入项：用户名、密码；账号设置时还包括当前密码、新密码、确认密码。
- 输出结果：登录状态、当前用户名、错误提示。
- 验收标准：未登录无法访问工作台；登录成功后能自动刷新数据；登出后清空访问状态；可修改用户名和密码。
- 关联页面：登录页、账号设置弹窗。
- 关联接口：`POST /api/v1/auth/login`、`GET /api/v1/auth/session`、`POST /api/v1/auth/logout`、`PUT /api/v1/auth/credentials`。
- 关联业务规则：所有 `/api/v1/**` 业务接口需已登录后访问，健康检查除外。

#### FR-002 样例排产任务提交

- 业务目标：提供一个无需录入复杂业务数据即可演示排产闭环的入口。
- 触发条件：用户在主工作台点击“运行样例排产”。
- 前置条件：用户已登录，后端和求解器服务正常。
- 主要流程：
  1. 用户点击样例排产按钮。
  2. 后端生成样例资源、任务、停机窗口并创建排产任务。
  3. 前端收到任务编号并进入轮询状态。
- 异常流程：任务创建失败、后端异常、求解器不可用。
- 输入项：无前端输入，样例数据由系统内置生成。
- 输出结果：任务编号、任务状态、最终版本编号。
- 验收标准：点击后返回任务编号；后台可异步执行；成功时生成新版本并可自动加载。
- 关联页面：主工作台头部操作区。
- 关联接口：`POST /api/v1/schedule/jobs/sample`。
- 关联业务规则：样例场景默认包含多资源、停机窗口、目标权重和求解配置。

#### FR-003 通用排产任务提交 API

- 业务目标：为后续真实业务建模页或外部系统集成提供标准化排产入口。
- 触发条件：前端页面或外部调用方提交排产请求。
- 前置条件：调用方已登录，请求体字段合法。
- 主要流程：
  1. 提交请求体，包含场景名、开始时间、时域、资源、任务、停机、目标权重和求解参数。
  2. 后端校验资源引用和停机窗口合法性。
  3. 通过后创建后台排产任务。
- 异常流程：候选资源不存在、停机窗口非法、字段缺失、求解失败。
- 输入项：
  - 资源：`id`、`label`、`resourceType`、`sortOrder`
  - 任务：`id`、`label`、`productCode`、`durationMinutes`、`dueMinutes`、`priority`、`candidateResourceIds`、可选 pinned 字段
  - 停机：`resourceId`、开始/结束分钟、类型、来源、说明
  - 参数：目标权重、求解时间上限、并行线程数
- 输出结果：任务编号、任务状态。
- 验收标准：能接收标准请求体；非法资源和停机窗口被拒绝；合法请求可进入异步执行。
- 关联页面：当前无正式前端页面，先作为 API 能力存在。
- 关联接口：`POST /api/v1/schedule/jobs`。
- 关联业务规则：`candidateResourceIds` 必须引用已声明资源；停机窗口需满足 `0 <= start < end <= horizon`。

#### FR-004 排产任务状态轮询

- 业务目标：让用户明确知道后台排产进度和结果。
- 触发条件：任务创建成功后自动开始轮询。
- 前置条件：已有合法任务编号。
- 主要流程：
  1. 前端按固定间隔查询任务状态。
  2. 若状态为运行中则继续轮询。
  3. 若状态为完成则停止轮询并加载对应版本。
  4. 若状态为失败则停止轮询并提示失败原因。
- 异常流程：轮询接口报错、会话失效、网络中断。
- 输入项：任务编号。
- 输出结果：任务状态文案、错误信息、版本编号。
- 验收标准：至少支持 `SUBMITTED/RUNNING/DONE/FAILED` 的用户反馈；完成后自动跳转到最新版本结果。
- 关联页面：主工作台任务状态卡片。
- 关联接口：`GET /api/v1/schedule/jobs/{jobId}`。
- 关联业务规则：轮询结果为 `DONE` 时必须存在对应版本编号。

#### FR-005 版本列表与结果查看

- 业务目标：让用户能查看每次排产形成的版本，并理解结果质量。
- 触发条件：登录成功后刷新、任务完成后自动刷新、手动刷新、选择某个版本。
- 前置条件：系统中存在一个或多个版本。
- 主要流程：
  1. 加载版本列表。
  2. 默认选中目标版本并加载详情。
  3. 展示版本状态、创建时间、发布时间、KPI、Gantt 行和停机窗口。
- 异常流程：无版本、版本不存在、接口错误。
- 输入项：版本编号。
- 输出结果：版本摘要、Gantt 数据、KPI 指标。
- 验收标准：支持列表查看；支持查看版本详情和 Gantt 数据；空状态有明确提示。
- 关联页面：版本面板、Viewer 区、KPI 面板、Gantt 区。
- 关联接口：`GET /api/v1/versions`、`GET /api/v1/versions/{versionId}`、`GET /api/v1/versions/{versionId}/gantt-data`。
- 关联业务规则：每个成功求解结果生成一个草稿版本；版本包含资源行、任务条、停机窗口和 KPI 快照。

#### FR-006 Gantt 本地交互

- 业务目标：提升排产结果的可解释性和可探索性。
- 触发条件：用户打开版本结果后查看或操作 Gantt。
- 前置条件：当前版本存在 Gantt 行数据。
- 主要流程：
  1. 用户查看资源时间轴、任务条和停机窗口。
  2. 用户可以缩放时间轴、查看详情、展开图例。
  3. 对非 pinned 任务可进行本地拖拽，形成本地草稿。
  4. 系统对本地草稿与任务/停机重叠进行冲突提示。
- 异常流程：无行数据、无版本选中、拖拽冲突。
- 输入项：当前版本 Gantt 数据和本地交互动作。
- 输出结果：缩放后的视图、本地草稿状态、冲突提示、详情展示。
- 验收标准：支持缩放、适配时间轴、查看详情；本地草稿可重置；冲突任务有显著标识；当前版本不要求回写后端。
- 关联页面：Viewer 区 Gantt 面板。
- 关联接口：依赖 `GET /api/v1/versions/{versionId}/gantt-data` 加载数据。
- 关联业务规则：pinned 任务只读；本地草稿仅影响前端展示，不改变已保存版本。

#### FR-007 版本发布

- 业务目标：明确当前确认采用的排产方案。
- 触发条件：用户在查看某个草稿版本时点击发布。
- 前置条件：已有选中版本，且版本状态不是已发布。
- 主要流程：
  1. 用户点击发布。
  2. 系统调用发布接口更新版本状态。
  3. 刷新版本列表和当前版本详情。
- 异常流程：发布失败、接口错误、会话失效。
- 输入项：版本编号。
- 输出结果：版本状态更新、发布时间更新、前端状态提示。
- 验收标准：草稿版本可发布；已发布版本按钮禁用；发布后列表和详情状态一致。
- 关联页面：Viewer 区操作按钮、版本列表。
- 关联接口：`POST /api/v1/versions/{versionId}/publish`。
- 关联业务规则：同一个版本重复发布不应成为常规操作；当前发布代表方案确认状态，不代表已下发到执行系统。

#### FR-008 账号设置与国际化

- 业务目标：保证系统基础可用性和可读性。
- 触发条件：用户切换语言、打开账号设置、提交账号修改。
- 前置条件：用户已登录。
- 主要流程：
  1. 用户可切换中英文界面。
  2. 用户可在账号设置中修改用户名和密码。
  3. 修改成功后即时刷新当前会话用户名。
- 异常流程：当前密码错误、密码过短、两次新密码不一致。
- 输入项：目标语言、用户名、当前密码、新密码。
- 输出结果：切换后的文案、账号修改结果。
- 验收标准：语言切换即时生效；密码规则有效；修改后会话仍可用。
- 关联页面：登录页、账号设置弹窗。
- 关联接口：`PUT /api/v1/auth/credentials`。
- 关联业务规则：新密码长度至少 6 位。

#### FR-009 版本治理增强

- 业务目标：支撑方案比较、回滚和审计化管理，推进试点落地。
- 触发条件：进入下一阶段版本治理建设。
- 前置条件：当前版本机制稳定。
- 主要流程：后续定义。
- 异常流程：后续定义。
- 输入项：后续定义。
- 输出结果：版本 diff、发布历史、真实回滚结果、审计记录。
- 验收标准：本期只作为规划项，不作为当前 POC 验收条件。
- 关联页面：后续定义。
- 关联接口：当前已有 `POST /api/v1/versions/{versionId}/rollback`，但业务语义需重新明确。
- 关联业务规则：回滚不应等同于简单再次发布，需要具备历史恢复和审计能力。

## 7. 非功能要求引用

| 类别 | 要求 | 指标/说明 | 是否本期必需 |

| 性能 | 后台求解应在可接受时间内返回可行解 | 当前默认求解时间上限 10 秒；前端通过异步任务避免阻塞页面 | 是 |
