## 2. 背景与目标

当前系统已完成登录、样例排产、异步轮询、Solver 求解、版本沉淀、Gantt 查看、导入导出和版本治理 smoke。针对 Snow Beer POC，当前已验证能力主要集中在智能包装计划排程，还不能覆盖客户要求的全部业务场景。

下一阶段的核心问题分三步：第三期先补齐 Snow Beer 主业务链路排程演示能力；第四期再补齐 Snow Beer POC 复杂业务场景，使全场景可演示、可解释；第五期最后补齐性能优化、审批治理、UI 优化和发布门禁，支撑 `pre-release` 推进到第一版正式 `release`。

本 PRD 的目标是明确：

1. 当前 POC baseline 哪些能力继续作为基础能力复用。
2. MVP/UAT 阶段必须新增哪些能力。
3. Snow Beer POC 第三期必须覆盖哪些主链路排程演示能力。
4. 第四期需要补齐哪些复杂业务场景。
5. 第五期哪些性能、审批、UI 和发布级要求需要作为正式 release 门槛。
6. 哪些高级 APS 能力明确后置，不阻塞当前阶段。
7. 每项需求的验收口径和边界。

## 3. 目标用户

| 算法/研发支持 | 分析求解失败、维护约束和回归样本 | 快速定位数据、约束和性能问题 | 中 |

## 5. 功能范围

### 5.1 已具备基线能力

- 登录、登出、会话校验、账号设置、中英双语切换。
- 样例排产任务提交。
- 通用排产任务提交 API。
- 排产任务状态轮询与失败反馈。
- 版本列表、版本详情、KPI 展示、Gantt 展示。
- 版本说明、提交待发布、发布、回退、history、diff、审计事件基础能力。
- 资源、任务、停机窗口导入导出基础能力。
- Gantt 缩放、图例、详情、本地草稿拖拽、锁定/解锁、冲突提示和试算。

### 5.2 MVP/UAT 必须新增或强化

- 真实/脱敏样本包和字段映射冻结。
- Resource / Recipe / Demand / Downtime 主数据模板和导入校验。
- 导入错误报告和导入版本记录。
- 从 Demand + Recipe 生成 Operation 的排产场景。
- Solver 支持工序先后 precedence、基础换型 setup、失败原因分类。
- 异步执行状态机和可观测性增强。
- Gantt 评审能力：定位、筛选、异常高亮、业务字段详情。
- 版本审批流、actor attribution、release notes、权限矩阵。
- UAT 测试计划、用例、缺陷跟踪和验收报告。

### 5.3 Snow Beer 第三期主链路排程演示范围

第三期目标是把 Snow Beer POC 从当前包装计划排程子场景推进到主业务链路可演示：

- 需求计划接入：订单/预测需求、SKU、数量、交期、优先级。
- 需求到生产任务生成：库存覆盖、剩余需求拆分、任务与需求追溯。
- 包材齐套基础校验：包材库存、物料需求、缺料识别。
- 糖化、发酵、过滤、包装离散化任务建模。
- 基础 precedence、setup、班次/停机、临时订单插单。
- 基础不可行解释：产能不足、物料不足、窗口冲突、无可用资源。
- 一条端到端客户演示脚本。

当前已新增第三期主链路样本包 `docs/sample-packages/snow_beer_main_chain_phase3/`，并通过导入批次、场景生成、solver 求解和 Gantt 数据 smoke。该样本用 3 条需求生成 12 个离散任务、9 条 precedence，覆盖 finished-goods 库存覆盖、原料/包材库存、糖化、发酵、过滤、包装、插单优先级、停机和包装换型。

第三期验收不以复杂行业规则精确建模、发布级性能、正式审批治理或 UI 精修为阻断项。

### 5.4 Snow Beer 第四期全业务场景补齐范围

第四期目标是在第三期主链路可演示后，补齐 Snow Beer POC 的复杂业务场景：

- 发酵成熟窗口的 POC 级建模。
- 发酵罐容量、占用、不可混装的最小可演示模型。
- 多锅次与发酵罐关系的近似或明确边界。
- 过滤到清酒的转换关系。
- 清酒罐中转、静置/保鲜窗口的 POC 级约束。
- 物料可用时间与缺料影响。
- 全场景样本包、全场景回归和业务解释。

第四期验收必须保证 Snow Beer POC 每个业务场景都有可运行样本、演示路径和结果解释；性能、审批治理、UI 精修和 release gate 进入第五期。

### 5.5 第五期发布级产品化范围

第五期目标是在第四期全场景能力补齐后，完成第一版正式 release 所需的产品化能力：

- 性能优化：Snow Beer 全场景样本的求解时间、导入速度、Gantt 渲染和大样本回归。
- 执行稳定性：队列化、超时、取消、重试、完整状态机和可观测性。
- 审批与版本治理：角色权限、提交审批、审批/驳回、发布、回退、actor attribution 和审计。
- UI/交互优化：业务场景入口、缺料/延期/换型/冲突高亮、方案对比、导入错误可读性。
- 发布治理：全场景 smoke、UAT 报告、操作手册、发布说明、release checklist 和回退方案。

第五期 release gate 无阻断项后，才将 `pre-release` 推进为第一版正式 `release`。

### 5.6 当前阶段明确不做

- 不覆盖所有车间、产品和工厂。
- 不做完整 ERP/MES 双向闭环。
- 不一次性实现复杂库存、公用工程、人员班组、任务拆分/合批。
- 不实现复杂多级审批、电子签和企业级 SSO。
- 不把 Gantt 本地拖拽直接保存为正式版本。

## 7. 单项需求说明

### FR-001 登录与会话管理

- 业务目标：确保排产数据和版本只对已登录用户开放。
- 验收标准：未登录不可访问业务接口；登录成功后自动加载版本；401 后清空状态并回登录页；账号修改需校验当前密码。
- 关联接口：`POST /api/v1/auth/login`、`GET /api/v1/auth/session`、`POST /api/v1/auth/logout`、`PUT /api/v1/auth/credentials`。

### FR-002 样例排产任务提交

- 业务目标：提供稳定演示入口和 smoke 基线。
- 验收标准：点击后返回 jobId；后台异步执行；成功生成版本；失败展示原因。
- 关联接口：`POST /api/v1/schedule/jobs/sample`。

### FR-003 通用排产 API

- 业务目标：作为前端建模、导入场景和外部系统集成的共同排产入口。
- 验收标准：合法请求进入异步执行；非法资源引用、停机窗口等返回 4xx；成功后可查询 job 和版本。
- 关联接口：`POST /api/v1/schedule/jobs`。

### FR-004 任务状态轮询

- 业务目标：让用户知道排程正在执行、完成或失败。
- 验收标准：至少展示提交中、运行中、完成、失败；完成后自动加载新版本；失败展示错误信息。
- 关联接口：`GET /api/v1/schedule/jobs/{jobId}`。

### FR-005 版本与 Gantt 查看

- 业务目标：让业务用户理解排程结果。
- 验收标准：支持版本列表、版本摘要、KPI、Gantt rows/bars/downtimes；空态和错误态清晰。
- 关联接口：`GET /api/v1/versions`、`GET /api/v1/versions/{versionId}`、`GET /api/v1/versions/{versionId}/gantt-data`。

### FR-006 Gantt 本地交互与试算

- 业务目标：支持用户探索局部调整影响。
- 验收标准：缩放、详情、拖拽、重置、冲突提示、锁定/解锁、试算主路径可用；明确本地草稿不等于正式版本。
- 关联接口：`POST /api/v1/versions/{versionId}/trial-solve`。

### FR-007 版本治理基础

- 业务目标：支持版本说明、待发布、发布、回退和审计基础。
- 验收标准：状态流转符合定义；history/diff/audit 可查看；发布和回退有明确记录。
- 关联接口：`GET /api/v1/versions/{versionId}/history`、`GET /api/v1/versions/{versionId}/diff`、`PUT /release-note`、`POST /ready-for-release`、`POST /publish`、`POST /rollback`。

### FR-008 主数据导入 MVP

- 业务目标：让真实或脱敏真实数据进入系统。
- 主要范围：Resource、Recipe、Demand、Downtime 模板；字段校验；引用校验；错误报告；导入版本记录。
- 验收标准：UAT_v1 样本可导入；非法数据定位到行/字段/原因；导入数据可生成场景。

### FR-009 排产场景生成

- 业务目标：把业务主数据转换为 solver 可用请求。
- 主要范围：Demand + Recipe 展开 Operation；生成任务、候选资源、工序关系、horizon、目标权重和 solver 参数。
- 验收标准：同一数据版本可复现场景；生成结果可提交排程；转换规则有文档。

### FR-010 Solver Must 约束

- 业务目标：让 UAT 结果符合必须遵守的业务约束。
- 主要范围：资源能力、停机、固定资源/开始、工序先后、基础换型、交期/优先级、失败原因分类。
- 验收标准：Must 硬约束 100% 不违反；不可行/超时/资源不足可解释；真实样本回归通过。

### FR-011 异步执行稳定性

- 业务目标：支撑多任务、长耗时和 UAT 问题定位。
- 主要范围：队列、状态机、超时、取消、重试策略、jobId/requestId/耗时/错误分类。
- 验收标准：多任务状态不丢失；solver 不可达和超时有明确失败状态；可通过 jobId 定位。

### FR-012 Gantt 业务评审

- 业务目标：让 Gantt 成为排产方案评审工具。
- 主要范围：订单、产品、资源、异常任务定位；迟交、固定、软约束影响提示；版本差异入口。
- 验收标准：业务用户 5 分钟内能定位一个订单的全部工序；异常任务可筛选；版本数据和 Gantt 一致。

### FR-013 审批与角色权限

- 业务目标：让正式版本发布成为可控业务动作。
- 主要范围：Admin、Planner、Approver、Viewer；提交审批、审批通过/驳回、发布、回退、actor 追踪。
- 验收标准：未审批版本不能直接发布；关键操作有后端权限校验；每个正式版本可追踪创建、提交、审批、发布和原因。

### FR-014 UAT 与发布收口

- 业务目标：形成可执行、可记录、可复盘的 UAT。
- 主要范围：UAT 用例、数据包、缺陷分级、回归报告、操作手册、验收报告。
- 验收标准：核心用例通过率 100%；P0 缺陷为 0；P1 缺陷有规避方案；业务方形成书面结论。

### FR-015 Snow Beer 主链路排程演示

- 业务目标：让第三期结束后可以向客户演示 Snow Beer 从需求到包装的主业务链路排程能力。
- 主要范围：需求计划、库存覆盖、包材齐套基础校验、糖化/发酵/过滤/包装离散化任务、班次/停机、换型、临时订单插单、基础不可行解释。
- 当前验证：`docs/sample-packages/snow_beer_main_chain_phase3/` 已覆盖 3 条需求、12 个离散任务、9 条 precedence，并通过 `scripts/uat_package_smoke.py` 形成 `SUCCEEDED / OPTIMAL` 结果和 12 条 Gantt bars。
- 回归入口：`backend/src/test/java/com/apspoc/backend/service/ScenarioGenerationServiceTest.java` 覆盖四段链路展开和物料传递；`solver/tests/test_solver_service.py` 覆盖四段 precedence、停机避让和包材不足不可行。
- 建模边界：第三期不要求连续流、浓度/收率、成熟窗口、清酒罐中转、多锅次满罐等行业规则精确建模。
- 验收标准：Snow Beer 主链路有可运行样本、演示路径、排程结果和业务解释；复杂行业规则和发布级产品化问题进入第四期/第五期。

### FR-016 Snow Beer 全业务场景补齐

- 业务目标：让第四期结束后可以覆盖 Snow Beer POC 要求的全部业务场景演示能力。
- 主要范围：发酵成熟窗口、发酵罐容量/占用/不可混装、多锅次与发酵罐关系、过滤到清酒转换、清酒罐中转、静置/保鲜窗口、物料可用时间、全场景样本和业务解释。
- 建模边界：允许采用 POC 级近似模型，但每个近似都必须写清楚适用边界和后续精确化方向。
- 验收标准：每个 Snow Beer POC 场景都有可运行样本、演示路径、排程结果或业务化失败原因。

### FR-017 发布级产品化

- 业务目标：让第五期结束后基本具备把 `pre-release` 推进为第一版正式 `release` 的条件。
- 主要范围：性能优化、队列与状态机、审批/驳回、角色权限、actor attribution、UI/交互优化、全场景回归、发布说明、操作手册、release checklist、回退方案。
- 验收标准：Snow Beer 全场景回归和发布 smoke 通过；性能达到发布基线；关键审批与发布动作可追溯；UI 可支撑客户演示和业务评审；正式 release 检查清单无阻断项。
