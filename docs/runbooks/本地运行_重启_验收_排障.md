# 本地运行、重启、验收与排障

## 1. 一键启动与停止

### 启动全部本地服务

```bash
./startup.sh
```

默认会处理：

- PostgreSQL / Redis 基础设施检查
- solver `8000`
- backend `8081`
- frontend `8080`

### 停止全部本地服务

```bash
./stop.sh
```

### 整体重启

```bash
./stop.sh
./startup.sh
```

## 2. 单服务启动与重启

### frontend `8080`

启动：

```bash
python3 -m http.server 8080 -d backend/src/main/resources/static
```

检查：

```bash
lsof -nP -iTCP:8080 -sTCP:LISTEN
curl -I -s http://127.0.0.1:8080/
curl -I -s http://127.0.0.1:8080/app.js
```

### backend `8081`

启动：

```bash
cd backend
SERVER_PORT=8081 mvn spring-boot:run
```

检查：

```bash
lsof -nP -iTCP:8081 -sTCP:LISTEN
curl -s http://127.0.0.1:8081/actuator/health
curl -i -s http://127.0.0.1:8081/api/v1/health
```

### solver `8000`

启动：

```bash
cd solver
python3 -m uvicorn app.main:app --reload --port 8000
```

检查：

```bash
lsof -nP -iTCP:8000 -sTCP:LISTEN
curl -s http://127.0.0.1:8000/health
```

## 3. 发布前回归

### 自动化回归

```bash
./scripts/verify-release.sh --tests-only
```

### 本地三端与 API smoke

```bash
./scripts/verify-release.sh --smoke-only
```

当前 smoke 默认覆盖：

- 登录、会话、样例排程、版本 diff
- 模板导出、资源/任务/停机最小导入
- Recipe / Demand / InventoryBalance 导入批次生成场景
- 物料平衡可行/不可行校验
- 版本说明、提交待发布、发布、回退、审计历史

### UAT sample package 端到端 smoke

```bash
rtk python3 scripts/uat_package_smoke.py
```

适用场景：

- 只验证 `docs/sample-packages/UAT_v1_sample_package` 这一套 canonical CSV 是否能打通
- 覆盖 `import-batch -> scenario generation -> schedule job`
- 不触发 release smoke 中的发布、回退、审计治理动作

### 全量执行

```bash
./scripts/verify-release.sh
```

smoke 汇总结果默认写到：

```text
.runtime/release-smoke-summary.json
```

UAT package smoke 汇总默认写到：

```text
.runtime/uat-package-smoke-summary.json
```

## 5. 本地工作区约定

### `auto_switch_proxy.py` 不属于 APS 项目提交范围

- 根目录下的 `auto_switch_proxy.py` 属于本机上的其他项目/本地辅助脚本，不属于 APS 项目的发布内容
- 后续进行 APS 的 `git add`、提交整理、发布验收时，都不要把它算进提交范围
- 如果它只是本地临时改动，不需要为了 APS 提交去整理或解释它

### 如果它反复出现在 `git status`

可在当前本地仓库执行：

```bash
git update-index --skip-worktree auto_switch_proxy.py
```

需要恢复正常跟踪时执行：

```bash
git update-index --no-skip-worktree auto_switch_proxy.py
```

## 6. 常见问题

### 页面明明改了，但浏览器里看不到

- 先硬刷新浏览器
- 再确认 `index.html` 里的静态资源版本号是否已更新
- 仍不生效时，检查 `8080` 是否仍在提供旧目录或旧进程

### backend 启动时出现 `HHH10001005: Database info`

这通常是 Hibernate 输出的数据库连接池信息，不是错误。  
只要后续 `8081` 健康检查返回 `200/UP`，就说明 backend 已正常启动。

### 新建排程请求导入失败

要区分两类文件：

- 可直接导入接口的 canonical CSV / Excel 模板
- 业务调研阶段的 staging / mapping CSV

`docs/sample-packages/chemical_plant_real_v1_draft/07_resource_staging.csv` 这类文件不是直接导入格式，不能直接发给 `/api/v1/model-import/*`。

### 版本 diff 能看到“当前已锁定”，但点进去仍拖不动

- 先确认浏览器已经加载最新的 `app.js`
- 再确认该任务是否仍处于锁定态
- 对于“基线未锁定，当前已锁定”的任务，当前实现支持从“变更任务”点击后自动解锁成草稿态，再到 Gantt 中拖拽
- 最新前端行为中，点击 `新增 / 调整 / 移除` 变更项后，至少应该看到以下之一：任务条强化高亮、资源行高亮、状态区提示
- 如果点击后完全无反馈，优先怀疑浏览器仍在使用旧版静态资源，先强刷页面再重试

### 拖拽时间标签被任务条挡住，或看起来没有“浮起来”

- 先确认浏览器已经加载最新的 `styles.css`
- 当前实现中，拖拽开始/结束时间应显示为悬浮卡片，并位于任务条上层
- 当前行在拖拽预览时会临时允许 `overflow: visible`，用于展示时间卡片；如果仍被遮挡，通常是静态资源缓存未更新
- 若只在个别浏览器出现，可先强刷页面，再观察是否仍复现

### `401 Authentication required`

- 先重新登录
- 再确认请求是否带上会话 cookie
- `login`、`session`、`logout`、`health` 以外的大多数 `/api/v1/*` 接口都要求已认证
