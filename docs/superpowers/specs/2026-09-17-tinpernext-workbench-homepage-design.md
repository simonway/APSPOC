# TinperNext 风格 React 工作台首页设计

## 1. 背景与目标

APSPOC React 工作台已完成第一阶段的旧版 APSPOC + YonBIP/TinperNext 配色和视觉 Token 统一。本阶段开始第二阶段，先改造 React 工作台首页，使其在布局层级、组件职责和操作优先级上更接近 TinperNext 企业工作台。

本设计只覆盖首页，不重写全局壳层、排程任务中心、数据导入表单、场景生成流程或 Gantt。首页改造完成后，其他页面继续沿用现有导航和行为，并在后续独立设计批次中逐步迁移。

## 2. 设计参考

- TinperNext / YonDesign：顶部品牌区、搜索区、一级模块导航、清晰的页面标题层级、标准化组件、单一主操作、模块化内容区。
- YonBIP 工作台：浅色企业工作台背景、白色内容表面、深色侧边工具栏、轻边界和轻阴影、品牌色用于关键强调。
- APSPOC 旧版静态 UI：APSPOC 品牌红、业务状态色、排程/版本/发布的业务语义。

本阶段继续使用已完成的视觉 Token，不引入新的颜色体系。

## 3. 产品目标

用户进入 React 工作台首页后，应在一个首屏内回答：

- 当前在哪个工作台模块？
- 当前排程和版本整体状态如何？
- 下一步最重要的动作是什么？
- 如何快速进入数据导入、场景生成、排程任务和版本发布？
- 发生错误时如何恢复？

“运行排程”是首页唯一主操作，其余入口必须降低视觉层级。

## 4. 信息架构

```text
顶部全局导航
  品牌区 | 一级模块 | 全局搜索 | 工具入口 | 用户

首页标题区
  当前模块上下文
  页面标题：智能排产工作台
  页面说明
  唯一主操作：运行排程

核心指标区
  排程版本 | 已发布版本 | 草稿版本 | 平均利用率

业务状态区
  待排程任务 | 排程通知 | 预警 / 冲突

快捷应用区
  下载导入模板 | 数据导入 | 场景生成 | 查看排程任务 | 版本发布

右侧状态摘要
  当前排程状态 | 发布队列 | 审计与治理
```

### 4.1 标题区

标题区新增明确的页面标题和说明，并把现有样例排程操作提升为标题区唯一主按钮。刷新保留为次级图标按钮。页面标题区不重复展示第二个“运行排程”按钮。

### 4.2 指标区

指标区继续读取 `DashboardSummary`，展示版本数、已发布、草稿和平均利用率。指标卡是纯展示组件，不发起请求、不承担导航行为。空值显示现有中文降级文案或数字 0。

### 4.3 业务状态区

业务状态区展示待排程任务、排程通知和预警/冲突。状态必须同时使用文字、图标和语义色表达。状态区可以提供一个明确的“查看排程任务”文本入口，但不能把每个指标卡变成隐式按钮。

### 4.4 快捷应用区

快捷应用是次级模块入口，使用图标、名称和简短说明。React 已有模块使用内部切换：数据导入、场景生成、排程任务。模板入口保留下载行为。尚未迁移到 React 的版本发布能力继续显式打开旧版控制台，并标明“旧版控制台”。

### 4.5 右侧状态摘要

右侧状态摘要保留当前排程、发布队列、审计治理三个业务信息块，但降低说明性营销文案比例，优先展示状态、版本和下一步动作。审计治理仍可通过旧版控制台继续查看。

## 5. 组件边界

### 5.1 App.tsx

`App.tsx` 继续负责认证后的页面选择、当前工作区和右侧工具状态。它向 `WorkspaceDashboard` 传递 `summary`、当前模块标签、当前工具标签和刷新回调。不在 `App.tsx` 中新增首页业务计算。

### 5.2 WorkspaceDashboard.tsx

首页组件负责区域编排和数据传递，目标结构为：

```tsx
<WorkspaceDashboard>
  <WorkspacePageHeader />
  <WorkspaceMetrics />
  <WorkspaceStatusOverview />
  <WorkspaceQuickApps />
  <WorkspaceSideSummary />
</WorkspaceDashboard>
```

第一批可以在现有文件内完成区域重组；只有在文件继续出现明显职责膨胀时才拆分子组件。不要提前引入新的全局状态或通用页面框架。

### 5.3 WorkspacePageHeader

负责当前上下文、标题、说明和“运行排程”主按钮。样例排程继续复用 `useSampleScheduleAction`，保持请求、加载、成功和失败行为不变。

### 5.4 WorkspaceMetrics

只接收 `DashboardSummary` 并渲染核心指标，不发起请求、不维护状态。

### 5.5 WorkspaceStatusOverview

只接收 `DashboardSummary` 并渲染业务状态，同时提供明确文本入口。颜色不是唯一语义来源。

### 5.6 WorkspaceQuickApps

负责次级快捷入口和导航回调，不维护 API 状态。内部 React 模块使用现有 `onOpenJobs` 或工作区选择机制，外部旧版入口使用现有 `resolveLegacyUiUrl`。

### 5.7 WorkspaceSideSummary

负责当前排程、发布队列和治理摘要；只消费 `DashboardSummary`，不改变后端数据流。

## 6. 数据流

```text
useDashboardData
  ├── session / role
  ├── backend health
  └── version summaries
          ↓
  createDashboardSummary
          ↓
  WorkspaceDashboard
          ├── header: useSampleScheduleAction
          ├── metrics: summary
          ├── status: summary
          ├── quick apps: navigation callbacks
          └── side summary: summary
```

认证、后端健康、版本列表和样例排程 API 均沿用现有实现。本阶段不新增后端接口，不改变 `DashboardSummary` 的字段契约。

## 7. 交互行为

- “运行排程”请求中显示加载状态，并禁止重复提交。
- 成功后在标题区下方显示任务编号和状态；如果生成版本，显示版本编号。
- 失败后只影响主操作反馈，保留已有指标和状态。
- 刷新保持为次级操作，继续使用 `dashboardData.reload`。
- 数据导入、场景生成、排程任务在 React 内部切换。
- 下载模板继续下载或打开模板 URL。
- 版本发布继续显式进入旧版控制台。
- 所有快捷入口支持键盘焦点和可读的按钮/链接名称。

## 8. 响应式行为

- 桌面端：标题区横向排列，指标四列，主体区域左右分栏。
- 中等宽度：指标两列，右侧摘要移动到主内容下方。
- 小屏：单列排列，主按钮保持可见，快捷应用变为纵向或两列。
- 现有左侧导航窄屏策略保持不变，本阶段不改造全局壳层导航。
- 不引入横向页面滚动；卡片内容允许自然换行。

## 9. 错误处理与可访问性

- 工作台整体不可用继续由 `App` 显示工作台级错误和“重新加载”。
- 样例排程错误在标题区附近显示，主按钮恢复可用。
- 指标字段缺失显示现有中文降级文案，不隐藏整个区域。
- 语义状态同时使用文本、图标和颜色。
- 标题层级保持 `h1` 页面标题、`h2` 区域标题。
- 主操作、次级操作和外部链接有清晰可访问名称。
- 加载状态使用 `role="status"` 或 Ant Design 的既有可访问反馈。

## 10. 测试计划

使用 TDD 增加行为测试：

1. 首页显示页面标题区和唯一“运行排程”主按钮。
2. 首页不存在第二个“运行排程”按钮。
3. 点击标题区主按钮仍调用现有样例排程 API，并显示加载、成功和失败反馈。
4. 数据导入、场景生成、排程任务快捷入口进入正确 React 页面。
5. 指标值和业务状态继续来自 `DashboardSummary`。
6. 版本发布和治理入口保持明确旧版控制台链接。
7. 小屏布局的关键元素存在且主按钮可访问。
8. 现有登录、仪表盘、排程任务、导入/场景工作流测试继续通过。

## 11. 验收标准

1. 首页具有 TinperNext 风格的“标题—说明—主操作—内容区”层级。
2. “运行排程”是首页唯一主操作，且位于页面标题区。
3. 指标、业务状态、快捷入口和右侧摘要职责清晰。
4. React 内部模块继续内部切换，未迁移能力明确进入旧版控制台。
5. 现有 API、数据模型、认证和权限行为不变。
6. 桌面、中等和小屏布局不产生页面级横向溢出。
7. 现有完整前端测试、构建、后端回归和运行验证通过。
8. 第二阶段后续的全局壳层、排程任务中心和其他页面改造保持独立，不混入本批。
