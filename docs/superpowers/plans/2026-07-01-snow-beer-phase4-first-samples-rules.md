# Snow Beer Phase 4 Material Availability Sample Package

This package validates the first Snow Beer Phase 4 material availability scenario with the current APS POC model.

## Scope

- demonstrates that material inventory can exist but become usable only after `availableFromMinutes`
- keeps the Phase 3 discrete main-chain operation pattern
- uses current builder and solver contracts without adding new rule files
- focuses on raw material and packaging material availability timing

## Explicitly Out of Scope

- fermentation maturity windows
- fermentation tank non-mixing and tank residency
- bright beer tank transfer
- stilling/freshness windows

- release-grade performance

# Snow Beer Phase 4 Maturity Window POC Sample Package

This package validates a POC approximation for fermentation maturity windows.

## Scope

- represents the maturity window as an explicit `MATURATION_WAIT` proxy operation
- keeps operation precedence auditable in generated metadata
- proves filtration cannot be reached until the maturity proxy completes
- uses current sample builder and solver contracts

## Explicitly Out of Scope

- precise tank residency modeling
- fermentation tank non-mixing
- multi-brew fill
- bright beer tank transfer
- stilling/freshness max window enforcement
- continuous-flow or concentration/yield rules

## Modeling Boundary

`MATURATION_WAIT` is a POC proxy. It is not exact fermentation tank occupation support. It makes the earliest-filtering business concept visible in the generated operation graph by adding a fixed-duration operation between fermentation and filtration.

`10_generated_operation_metadata.json` is the authoritative artifact for the `operationCode` value. The generated `08_generated_schedule_request.json` follows the current schedule request contract and does not carry an `operationCode` field; audit it through the task id `dem_a500_maturity_1224__03_maturation_wait`, the `成熟等待` label, `MATURED_A500_LOT` material flow, and predecessor links.

## Build

```bash

```

```bash

```

## Intended UAT Focus

- prove the generated operation graph can include an explicit maturity proxy
- prove precedence links fermentation to maturity and maturity to filtration
- explain why this is an approximation and not complete tank-residency support

## Talk Track

# 第四期发酵罐规则建模草案

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v0.1 |
| 当前状态 | 首版规则草案 |
| 适用阶段 | Snow Beer 第四期 |
| 更新时间 | 2026-07-01 |
| 相关样本 | `snow_beer_phase4_maturity_window`、后续 `snow_beer_phase4_fermentation_tank` |

> 本文档只冻结发酵罐容量、占用和不可混装的第一版规则语义，不声明当前系统已经精确支持这些规则。

## 2. 规则目标

第四期发酵罐规则要回答三类业务问题：

1. 罐体容量是否足够承接当前批次。
2. 罐体在发酵和成熟占用窗口内是否可用。
3. 同一罐体是否允许混装不同产品族、批次或状态。

## 3. 当前支持状态

| 规则 | 当前状态 | 说明 |
| --- | --- | --- |
| 发酵作为离散任务 | 已支持 | Phase 3 已用 `FERMENTATION` 任务表达 |
| 成熟窗口 POC 代理 | POC 近似 | `MATURATION_WAIT` 可表达等待语义，但不是精确罐占用 |
| 罐体容量 | 未精确支持 | 当前资源 `capacity` 是说明字段，不进入 solver 容量计算 |
| 罐体占用窗口 | 未精确支持 | 当前任务只占用自身操作时段，未覆盖成熟后驻留 |
| 不可混装 | 未支持 | 当前 setupGroup 不能表达同罐混装约束 |
| 多锅次满罐 | 后置 | 需单独定义聚合/拆分语义 |

## 4. 第一版建模词汇

| 概念 | 建议字段 / 来源 | 业务含义 | 第一版建议 |
| --- | --- | --- | --- |
| `tankId` | resource id | 发酵罐资源编号 | 沿用 `02_resources.csv.id` |
| `tankCapacityUnits` | future rule file | 罐体可承接的代理 lot 单位 | 先用整数代理单位，后续再映射 KL |
| `batchVolumeUnits` | future rule file or demand extension | 当前批次占用代理单位 | 先固定为每 lot 1 单位 |
| `occupationStart` | generated fermentation start | 罐体占用开始 | 取发酵任务开始 |
| `occupationEnd` | generated maturity release | 罐体释放时间 | 精确模型应覆盖成熟完成或释放点 |
| `mixingFamily` | product family / setup group | 不可混装兼容性 | 第一版按产品族判断 |

## 5. 第一版规则语义

### 5.1 容量规则

同一占用窗口内，一个发酵罐承接的批次容量之和不能超过 `tankCapacityUnits`。

第一版建议：

- 用代理 lot 单位，不直接用 KL。
- 每个 demand lot 默认消耗 1 个容量单位。
- 如果客户提供真实 KL，再作为后续 refinement。

### 5.2 占用窗口规则

发酵罐占用窗口应从发酵开始持续到可释放点。

第一版建议：

- 若存在成熟窗口，释放点应晚于发酵结束。
- `MATURATION_WAIT` 当前只是 POC 代理，不能等价为真实罐占用。
- 精确支持需要 solver 能表达跨操作的资源占用。

### 5.3 不可混装规则

同一占用窗口内，同一罐体不能混装不兼容产品族。

第一版建议：

- 先按产品族或 setup group 定义兼容性。
- A500 与 B600 默认视为不兼容。
- 后续可扩展到酒种、浓度、批次状态等维度。

## 6. 失败解释口径

| 失败类型 | 面向业务的解释 |
| --- | --- |
| 无可用罐 | 当前候选发酵罐在所需占用窗口内均已被占用 |
| 容量不足 | 可用罐容量不足以承接当前批次 |
| 不可混装 | 候选罐中已有不兼容产品族或批次 |
| 成熟释放冲突 | 批次尚未达到释放条件，不能进入下游 |

## 7. 后续样本建议

后续 `snow_beer_phase4_fermentation_tank` 应至少包含：

- 成功样本：A500 与 B600 分配到不同罐或不同占用窗口。
- 容量失败样本：候选罐容量不足。
- 不可混装失败样本：两个不兼容批次被迫争用同一罐。
- 解释文档：说明失败原因不只是技术枚举。

## 8. 需要后续扩展的系统点

| 区域 | 需要扩展 |
| --- | --- |
| 样本契约 | 新增规则文件或扩展资源/配方字段表达容量和兼容性 |
| backend import | 校验罐规则字段、产品族兼容性和容量单位 |
| scenario generation | 将罐规则绑定到生成任务和物料/批次语义 |
| solver | 支持跨操作占用窗口、容量累计和不可混装约束 |
| Gantt / explain | 展示罐占用、释放点和失败原因 |

## 9. 当前结论

第一批 Phase 4 只提交规则草案，不把发酵罐容量、占用和不可混装写成已支持能力。等 material availability 和 maturity-window POC 样本稳定后，再单独开 `snow_beer_phase4_fermentation_tank` 实施切片。
```
