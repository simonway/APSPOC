# Snow Beer Phase 4 Material Availability Sample Package

This package validates the first Snow Beer Phase 4 material availability scenario with the current APS POC model.

## Scope

- demonstrates that material inventory can exist but become usable only after `availableFromMinutes`
- keeps the Phase 3 discrete main-chain operation pattern
- uses current builder and solver contracts without adding new rule files
- focuses on raw material and packaging material availability timing

## Explicitly Out of Scope

- fermentation maturity windows
- fermentation tank non-mixing and tank residency
- bright beer tank transfer
- stilling/freshness windows
- procurement reverse planning
- release-grade performance

## Files

- `01_request_context.csv`: scenario, horizon, objective, solver config
- `02_resources.csv`: sugarization, fermentation, filtration, packaging resources
- `03_recipes.csv`: four-step main-chain recipe per SKU
- `04_demands.csv`: demand slices that require delayed materials
- `05_downtimes.csv`: no downtime rows in this first sample
- `06_setup_rules.csv`: packaging family changeovers
- `07_data_issue_log.csv`: assumptions and Phase 4 boundaries
- `09_uat_expected_checks.md`: expected counts and semantic checks
- `14_inventory_balances.csv`: material inventory with non-zero availability checkpoints

Generated files:

- `08_generated_schedule_request.json`
- `10_generated_operation_metadata.json`
- `11_import_ready_resources.csv`
- `12_import_ready_tasks.csv`
- `13_import_ready_downtimes.csv`

## Intended UAT Focus

- prove the package can model material that is present in inventory but not usable until a future minute
- prove generated tasks preserve material inputs and outputs
- prove the solver material balance can use `availableFromMinutes` as an inventory event
- keep all other brewery-specific rules out of this package

## Material Availability Evidence

Use these source rows as the semantic checks for this package:

- `MALT_A_LOT` and `HOPS_A_LOT` are available at minute `240`, so A500 sugarization material is not usable at schedule minute `0`.
- `CAP_A_LOT`, `CTN_A_LOT`, and `LBL_A_LOT` are available at minute `540`, so A500 packaging material is delayed.
- `MALT_B_LOT` and `HOPS_B_LOT` are available at minute `0`, while `CAP_B_LOT`, `CTN_B_LOT`, and `LBL_B_LOT` are available at minute `1200`.
- `10_generated_operation_metadata.json` and `08_generated_schedule_request.json` must preserve these inventory availability values.
- `09_uat_expected_checks.md` is generated by the package builder and should be read together with this section for the material-specific acceptance points.

## Talk Track

This sample shows a Phase 4 material availability problem. Raw materials and packaging materials are not treated as instantly usable just because they exist in the inventory table. The `availableFromMinutes` value represents the first minute at which a material is usable by the schedule. This is current exact support through the material balance model, not a new approximation.

## Completion Criteria

The sample is complete when:

- build validation passes
- generated operation metadata contains four operations for each planned demand lot
- delayed materials appear in `14_inventory_balances.csv`
- generated tasks carry material inputs for the delayed items
- smoke or solver evidence confirms the request is schedulable
